# 工具安装与调试手册

## 1. 只安装这一套工具

| 工具                | 用途                | 是否必须 | 初学者动作                     |
| ----------------- | ----------------- | ---- | ------------------------- |
| IntelliJ IDEA     | 写 Java、运行若依、断点调试  | 必须   | 打开后端项目，设置正确 JDK/Maven。    |
| DBeaver Community | 看表、执行 SQL、核对数据    | 必须   | 建 MySQL 连接；只操作学习数据库。      |
| Apifox            | 发送接口请求、保存响应、做接口测试 | 必须   | 新建“档案系统”项目，保存每个接口。        |
| 浏览器 Chrome/Edge   | 看页面、前端网络请求        | 必须   | F12 打开 Network 和 Console。 |
| Git + GitHub      | 提交、推送和展示开发过程      | 必须   | 每天 2 次 `add/commit/push`。 |
| VS Code           | 仅用于看/改若依前端文件      | 推荐   | 不用在里面写 Java。              |

下载入口：[DBeaver Community](https://dbeaver.io/download/)、[Apifox](https://apifox.com/)、[Git for Windows](https://git-scm.com/install/windows)。DBeaver Community 是免费开源版本；Apifox 可用于接口调试和保存请求；IntelliJ IDEA 自带 Java 调试器。[DBeaver](https://dbeaver.io/download/) [Apifox 快速上手](https://docs.apifox.com/getting-started) [IDEA 调试文档](https://www.jetbrains.com/help/idea/debugging-code.html)

### 安装顺序（Day 1 上午完成）

1. 检查已有 JDK：在终端运行 `java -version` 与 `mvn -v`，把结果记录在 Day 1 笔记。
2. 打开 IDEA：`File → Open`，选择 **含有 `pom.xml` 的后端根目录**；等待右下角 Maven 导入完成。不要选择单个 `src` 文件夹。
3. 安装 DBeaver：`新建数据库连接 → MySQL → Host=localhost、Port=3306 → 填账号密码 → Test Connection`。第一次提示下载驱动可允许。
4. 安装 Apifox：新建项目“档案管理系统”；环境变量 `baseUrl=http://localhost:8080`（端口按你的源码实际为准）。
5. 安装 Git 并在终端运行 `git --version`；登录 GitHub 后创建空仓库，但不要勾选自动 README（本地项目已有文件）。

## 2. 看源码时要不要调试？

**要。** 前三天以“阅读 + 单步调试”为主；Day 4 后以“写一小段代码 + 调试验证”为主。阅读只能知道大致结构，调试才能确认真实参数、SQL 结果和代码实际走向。

不要一开始把断点打满项目。一次只跟踪一条最短路径，例如“新增一条档案”。

## 3. Java 后端标准调试流程（每天至少做一次）

以“新增档案”为例。若你生成的类名不同，找名称中包含 `Archive` 的对应类。

1. **先复现。** 用 Apifox 或页面提交一次新增档案，保存请求 JSON、响应和时间。
2. **找入口。** IDEA 全局搜索 `ArchiveController` 或搜索接口路径；在新增方法（通常叫 `add`、`create` 或 `insert`）第一行左边单击，出现红点就是断点。
3. **Debug 启动。** 点击启动配置旁的绿色小虫，不要点普通运行三角。等后端启动完成。
4. **再次发请求。** Apifox 发送同一请求；程序会暂停到断点。
5. **检查变量。** 在 Debug 面板看请求对象：编号、分类 ID、状态是否和请求一致；字段为空时，问题大概率在参数名、JSON 或前端表单。
6. **单步进入 Service。** `F7`（Step Into）进入调用的方法；遇到无关框架代码用 `F8`（Step Over）跳过。
7. **检查业务规则。** 在唯一校验、状态判断处看条件左右两边值；不要凭感觉改 `if`。
8. **检查 Mapper/SQL。** 在 Mapper 方法或 XML SQL 前打断点；同时打开 DBeaver，执行对应 `SELECT`，核对数据库实际是否已有记录。
9. **验证结果。** `F9` 继续；在 Apifox 看响应，在 DBeaver 刷新表确认数据，三处一致才算成功。
10. **移除断点、提交。** 红点再点一次移除；把复现/原因/修复写进当天模板，再 Git 提交。

### 快捷键最小集

| 动作 | IDEA Windows 快捷键 | 什么时候用 |
|---|---|---|
| 添加/移除断点 | 点击行号左侧 | 程序应停下检查状态处。 |
| 启动调试 | Shift + F9 | 需要断点时。 |
| 继续运行 | F9 | 当前检查完成。 |
| 单步跳过 | F8 | 不想进入方法内部。 |
| 单步进入 | F7 | 想看当前方法调用了什么。 |
| 跳出当前方法 | Shift + F8 | 已看完方法，回到调用者。 |
| 查看表达式 | Alt + F8 | 临时计算 `record.getStatus()` 等。 |

## 4. 前端与接口、数据库如何协同排错

### 页面点了按钮没有结果

1. 浏览器按 F12 → **Network** → 清空记录。
2. 再点一次按钮，找 `Fetch/XHR` 请求。
3. 看 Request URL、Payload、Status Code、Response。
4. 404：多数是前端 API 路径或后端映射错误；401/403：登录或权限；500：复制后端日志的完整异常。
5. 将同样 URL/参数放到 Apifox 请求。若 Apifox 成功但页面失败，查前端；两边失败则查后端。

### 后端返回成功，但数据不对

1. 在 DBeaver 执行与 Mapper 接近的 `SELECT`。
2. 核对库名、表名、where 条件、字段值，不要只看 IDE 配置。
3. SQL 正确但 Java 错：在 Mapper 返回处打断点，比较原始查询结果和实体字段。
4. Java 正确但页面错：在浏览器 Network 比较响应 JSON 和页面显示字段。

## 5. 不要做的事

- 不要在源码读不懂时直接全局替换或复制整段 AI 代码。
- 不要把 `application.yml` 中含密码的生产配置推到 GitHub。
- 不要在不理解的前提下升级 JDK、Spring Boot、Node 或若依版本。
- 不要在生产服务器用 root 账号运行应用或开放 MySQL 的 3306 到公网。
