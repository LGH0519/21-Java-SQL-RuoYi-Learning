# 20 天 Java + 若依二开学习计划

## 0. 计划边界与最终交付

**总时长：20 天 × 10 小时 = 200 小时。**

这是一份面向 Java 后端初学者的项目冲刺计划，不追求学完 Java 全部内容。目标是理解并完成一套若依二开项目，建立“需求 → 表设计 → 接口 → 页面 → 测试 → 部署”的完整能力链。

第 20 天必须交付：

1. GitHub 仓库 `archive-management-system`：若依二开的档案全生命周期管理系统；
2. GitHub 仓库 `library-management-api`：独立的 Spring Boot 图书管理 API；
3. 云服务器上可访问的主项目，副项目可通过 API 验证；
4. 两份 README、SQL 初始化脚本、接口测试记录、项目截图；
5. 一段 3–5 分钟项目讲解，以及简历项目描述。

### 项目范围（不能扩大）

主项目只做：档案分类、档案信息、借阅申请、归还、逾期状态、角色权限、查询/导出、统计。不要加入真实文件上传、工作流引擎、消息通知、多租户、微服务。

副项目只做：图书分类、图书、读者、借阅/归还，提供 REST API 和接口文档；不做复杂前端。

### 每日固定动作（每天 20 分钟）

- 早上开始前：看昨日笔记和未完成项，5 分钟。
- 晚上结束前：写一条不少于 100 字的学习日志，10 分钟。
- 每天至少 **2 次 Git 提交**；提交信息必须描述功能，例如 `feat: add archive borrowing validation`。
- 每天至少 **1 个可验证成果**：Java 练习运行结果、SQL 文件、接口响应、页面截图或测试记录。
- 卡住超过 30 分钟：先写下错误、已尝试的命令、期望结果，再询问 AI；不要无目的地反复搜索。

## 2. 必学知识清单（学到什么程度才算会）

### A. Java：42 小时

| 知识点 | 必须理解 | 能力验收 |
|---|---|---|
| 运行机制 | JDK、JRE、JVM；`javac` 编译与 `java` 运行 | 解释 `.java` 为什么会变成 `.class`，并从命令行运行程序。 |
| 语法 | 变量、基本类型、运算符、`if`、`switch`、`for`、`while` | 写 8 个控制台题：分数等级、闰年、九九表、求和等。 |
| 方法与数组 | 参数、返回值、重载、数组遍历 | 写“统计数组最大值/平均值”和“查找档案编号”。 |
| 面向对象 | 类、对象、封装、构造方法、继承、接口、多态 | 写 `Archive`、`BorrowRecord` 类，并用接口定义状态校验行为。 |
| 常用类 | `String`、`LocalDate`、`BigDecimal`（认识即可） | 用 `LocalDate` 计算是否逾期。 |
| 集合 | `List`、`Set`、`Map`、`for-each` | 把 10 条档案对象放入 `List`，按状态筛选、按编号去重。 |
| 异常 | `try/catch`、`throw`、自定义业务异常概念 | 对空编号、重复编号、非法状态抛出明确错误。 |
| 工程工具 | Maven 的 `pom.xml`、依赖、打包 | 找到若依或副项目的依赖，完成一次 `package`。 |

不学或只认识：多线程、网络编程、反射、JVM 调优、设计模式、复杂 Stream、算法竞赛题。它们不属于本 20 天项目的关键路径。

### B. MySQL：24 小时

| 知识点 | 必须理解 | 能力验收 |
|---|---|---|
| 关系建模 | 实体、字段、主键、外键概念、一对多 | 画出档案分类—档案、档案—借阅记录关系。 |
| DDL | `CREATE DATABASE/TABLE`、类型、主键、非空、唯一、默认值、`ALTER` | 不看资料建出 4 张业务表。 |
| DML | `INSERT`、`UPDATE`、`DELETE` | 为每张表插入至少 10 条测试数据。 |
| DQL | `SELECT`、`WHERE`、`LIKE`、`IN`、排序、分页 | 写出 15 条档案系统查询。 |
| 聚合连接 | `COUNT/SUM/AVG`、`GROUP BY`、`HAVING`、`LEFT JOIN` | 输出分类档案数、借阅中数量、逾期清单。 |
| 事务/索引 | ACID 概念；`BEGIN/COMMIT/ROLLBACK`；索引为何提高查询 | 借阅时“更新档案状态+新增记录”要么都成功，要么都失败。 |

### C. Spring Boot / MyBatis / 若依：34 小时

| 知识点 | 必须理解 | 能力验收 |
|---|---|---|
| 分层 | Controller 接收请求；Service 放业务规则；Mapper 访问数据库 | 画出一个列表查询的调用链。 |
| 注解 | `@RestController`、`@RequestMapping`、`@Service`、`@Autowired`/构造器注入、`@Transactional` | 在项目中找到并解释各自真实用途。 |
| 接口 | HTTP 方法、路径、参数、JSON、状态码 | 用 Apifox/Postman 调通 8 个 API。 |
| MyBatis | 实体、Mapper、SQL 映射、参数、结果映射 | 能定位一个查询的 Java 方法和对应 SQL。 |
| 若依 | 用户/角色/菜单/字典/权限/代码生成/导出/日志 | 用代码生成器创建一个模块，再手工补一条业务校验。 |
| 前端最小集 | HTML 表单与表格；JS 模块/异步请求概念；若依页面、API 文件、菜单 | 修改一个表单字段、一个列表列并联调成功。 |

## 5. AI Agent 使用规范

可以让 AI：解释源码、拆分需求、给出 SQL 初稿、生成重复 CRUD 骨架、分析报错、审查代码。

不能把 AI 输出不经阅读地直接提交。每次让 AI 给代码，先使用这段提示：

```text
我是 Java 初学者，正在基于若依开发档案管理模块。
请先解释我给出的文件中 Controller、Service、Mapper 和 SQL 的调用关系，
再列出实现需求所需修改的文件和原因。先不要给完整代码。
我确认后，再给我最小改动的代码，并为每个改动给出验证步骤。
需求是：档案编号必须唯一，借阅中档案不能重复借阅，归还后才能再次借阅。
```

收到代码后的四步：阅读每一行 → 自己复述作用 → 运行接口/页面 → 成功后提交。将报错完整贴给 AI，不要只说“不能运行”。
