# Day 20：把成果变成能讲清的能力

## 今日成果

你能无稿讲清一个项目；简历项目描述真实、具体；知道下一个 30 天该补什么。

| 时间 | 知识点 | 如何学习和操作 | 验收 |
|---|---|---|---|
| 09:00–10:30 | 项目讲解结构 | 写 3 分钟稿：背景→表设计→借阅事务/状态→权限/统计→部署。每段只说自己的真实工作。 | 不看稿讲完一次。 |
| 10:30–12:00 | 高频问题 | 回答：分层职责？主键/索引？事务？状态校验？接口如何测？权限？Redis 用在哪？如何部署？ | 每题 1–2 分钟。 |
| 15:00–16:30 | 简历项目描述 | 使用上一份总计划的简历模板；替换成你真正完成的功能、技术和数据。 | 一段主项目、一段副项目描述。 |
| 16:30–18:00 | GitHub 体检 | 检查仓库名、README、SQL、截图、提交历史、许可证/敏感信息。 | 仓库链接可公开展示。 |
| 19:00–20:30 | 全流程彩排 | 从 GitHub README 开始，启动/打开线上项目，演示核心流程。 | 5 分钟内完成。 |
| 20:30–22:00 | 复盘 | 写：最难的 3 个问题、如何解决、仍欠缺的知识。 | `final-retrospective.md` ≥500 字。 |
| 22:00–23:00 | 后续 30 天 | 排优先级：Java 集合/异常深入→MyBatis/Spring→SQL 索引→前端基础→算法/面试；不开始微服务。 | 下一阶段周计划。 |

## 必须验收

- [ ] 你的回答有真实代码、表、接口或部署证据，不夸大“独立架构设计”。
- [ ] 两个项目都能在 GitHub 找到，主项目可在公网演示。
