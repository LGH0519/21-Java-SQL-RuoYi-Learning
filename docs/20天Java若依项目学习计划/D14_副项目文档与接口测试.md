# Day 14：将 API 做成可验证作品

## 今日成果

副项目有 API 文档、测试集合、README、SQL 和清晰的错误响应；本地可从空库启动。

| 时间 | 知识点 | 如何学习和操作 | 资源 | 验收 |
|---|---|---|---|---|
| 09:00–10:30 | 命名与分层回顾 | 检查 Controller 不直接写业务判断、Service 不直接处理 HTTP；变量不拼音、不叫 `data1`。 | Day 3 笔记 | 修复 ≥5 处命名/职责问题。 |
| 10:30–12:00 | 统一错误响应 | 设计最小返回：`code/message/data`；参数或业务失败时有 message。 | Spring Boot 异常章节 | 3 种错误响应格式一致。 |
| 15:00–16:30 | Apifox 组织 | 分类：图书、读者、借阅；每个接口写名称、方法、URL、参数、示例响应。 | [Apifox 快速上手](https://docs.apifox.com/getting-started) | 至少 8 个已保存请求。 |
| 16:30–18:00 | README | 写项目用途、架构、表、启动、接口、事务说明、测试步骤。 | GitHub Markdown | README ≥500 字。 |
| 19:00–20:30 | 空库验证 | 新建干净数据库→导入 SQL→修改本地配置→启动→调用接口。 | DBeaver + Apifox | 从空库可复现。 |
| 20:30–22:00 | GitHub | 推送仓库，检查 README 和 SQL。 | Git | 副项目远程仓库可见。 |
| 22:00–23:00 | 调试复盘 | 找一个失败请求，按 Controller→Service→Mapper→DBeaver 走完。 | 调试手册 | 一条完整调试记录。 |

## 必须验收

- [ ] 接口测试不是“浏览器打开一下”，而是保存请求、参数、响应和失败场景。
