# Day 5：用若依生成第一个业务模块，并读懂生成代码

## 今日成果

档案分类模块和档案信息模块的基础 CRUD 可运行；你知道生成器帮你做了什么、没帮你做什么。

| 时间 | 知识点 | 学习与操作步骤 | 资源 | 验收 |
|---|---|---|---|---|
| 09:00–10:00 | 生成器输入是“表结构” | 将 Day 4 SQL 导入若依数据库；DBeaver 查看字段注释和类型。 | [若依代码生成](https://doc.ruoyi.vip/ruoyi/document/htsc.html) | 4 表出现在正确数据库。 |
| 10:00–12:00 | 生成档案分类 | 若依后台：系统工具→代码生成→导入表→选择 `archive_category`→预览→生成；先看 zip 内每类文件，再按目录复制。 | 若依代码生成 | 分类菜单可见，列表/新增/修改/删除可用。 |
| 15:00–16:20 | 读生成代码 | 打开分类 Entity、Controller、ServiceImpl、Mapper、XML、前端 API、Vue 页面。每个文件写一句职责。 | 源码 + Day 3 笔记 | `generated-code-map.md` 7 行说明。 |
| 16:20–18:00 | 生成档案信息 | 对 `archive_record` 重复流程；生成前检查字段展示类型、查询类型、是否必填。 | 若依代码生成 | 档案基础 CRUD 可用。 |
| 19:00–20:30 | 第一条手写规则 | 在档案新增 Service 中实现“档案编号不可重复”；先搜索生成的 `insert` 调用链，再新增查询方法。 | AI 模板 + 调试手册 | 重复编号返回明确失败提示。 |
| 20:30–21:40 | 调试新增档案 | 断点：Controller 新增方法→Service 新增方法→Mapper 插入前；Apifox 发送两次相同编号。 | 调试手册 | 记录第一次和第二次的变量/响应差异。 |
| 21:40–23:00 | 数据和提交 | 分类至少 5 条、档案至少 30 条；截图分类/档案页。 | DBeaver | ≥3 次提交；6 条接口测试记录。 |

## 必须验收

- [ ] 生成器只解决通用 CRUD；“编号唯一”等业务规则必须手写。
- [ ] 你能找到一条新增操作对应的 Controller、Service、Mapper、SQL 和前端页面。
