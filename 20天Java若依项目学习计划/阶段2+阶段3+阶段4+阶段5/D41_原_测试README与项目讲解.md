# Day 41：测试、README 与项目讲解

> 今日目标：建立不少于 15 个测试场景（至少 5 个失败场景），让陌生人能根据 README 本地理解和启动项目，并能进行 3 分钟项目讲解。

## 知识点速记（完成当天任务后复习）

- 测试用例最低要素：编号、角色、前置、步骤、预期、实际、证据、结论。
- 失败场景应覆盖权限不足、重复编号、非法状态、附件异常、事务失败。
- README 面向陌生协作者：背景、范围、技术栈、设计、启动、测试账号说明（不含密码）、已知限制。
- 讲解顺序：业务问题→表设计→核心状态/事务→权限/附件/逾期→运行验证。

## 本日重点、易混点与若依对应

“功能能点”不等于可交付。测试必须包含失败路径，README 必须提供不含秘密的可复现步骤。所有本机用户名、MySQL 密码、Token、真实路径和真实附件都不能进 README；使用 `application-*.yml.example` 或文字占位说明。

## 今天照做（09:00–23:00）

### 09:00–12:00｜建测试表并执行

1. 新建 `docs\test\test-cases-v1.md`，建表：编号、模块、角色、前置、步骤、预期、实际、证据、结论。
2. 至少填并执行 15 条：分类 CRUD、档案查询/新增、重复编号失败、借阅中删除失败、附件上传/下载、空/异常附件、提交/重复/撤销、审批/驳回、员工审批越权、借出/归还、逾期、事务失败回滚、权限不足。
3. 失败场景至少 5 条，实际结果不符时标失败并链接问题，不篡改结果。

### 15:00–18:00｜写 README

1. 项目根目录新建或更新 `README.md`，只改与本项目有关部分。
2. 使用以下章节：项目背景、V1 功能/不做项、角色、技术栈、架构/数据流、ER 图/表说明、启动前置、后端启动、前端启动、数据库初始化、测试方式、已知限制、第二版候选。
3. 启动说明写真实命令/端口并自己按顺序复现一次。配置密码改成 `<你的MySQL密码>`，不要提交真实值。
4. 添加少量脱敏截图，确保无 Token、账号密码、真实附件。

### 19:00–23:00｜三分钟讲解与复核

1. 写 3 分钟提纲：30 秒背景/角色，40 秒五表，50 秒申请→审批→借出→归还事务，30 秒权限/日志，20 秒附件/逾期，10 秒限制。
2. 对着本地运行项目讲一次并录音；听一遍，补一处含糊的字段/状态说明。
3. 用“新同事视角”只读 README，是否能从零完成：建库→导入 SQL→配本地参数→启动前后端→打开页面？不能则修说明。
