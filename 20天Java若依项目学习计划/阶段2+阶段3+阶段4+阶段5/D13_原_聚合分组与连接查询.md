# Day 13：聚合、分组与连接查询

> 今日目标：增加借阅申请学习表，能用聚合统计、INNER/LEFT JOIN 解答业务问题，并解释每个 JOIN 条件。

## 知识点速记（完成当天任务后复习）

- 聚合函数：`COUNT` 数量、`SUM` 总和、`AVG` 平均、`MAX/MIN` 最大最小。
- `GROUP BY` 把相同值分组后聚合；`HAVING` 筛选**分组后的结果**，`WHERE` 筛选原始行。
- `INNER JOIN` 只保留两侧都能关联上的行；`LEFT JOIN` 保留左表全部行，右侧没有匹配时为 NULL。
- 关联条件不是随意写：`r.category_id = c.id` 表示档案的分类编号对应分类主键。

## 本日重点、易混点与若依对应

业务问题决定 JOIN 类型：“每个分类有多少档案”要保留没有档案的分类，使用 LEFT JOIN；“当前借阅中的档案清单”只需要有借阅申请的档案，通常 INNER JOIN。`COUNT(*)` 统计连接产生的行；LEFT JOIN 中若要统计右表匹配数，应写 `COUNT(r.id)`，不能写 `COUNT(*)`，否则没有档案的分类也可能被计为 1。

面试点：WHERE 与 HAVING 的区别。简答：WHERE 在分组前过滤行，HAVING 在 GROUP BY 后过滤组。易混点：连接不是“把两张表机械拼接”；缺少正确 ON 条件会产生笛卡尔积，结果数异常巨大。

### 15:00–18:00｜写四类业务 SQL

1. 每分类档案数（必须包含没有档案的分类）：

```sql
SELECT c.id, c.category_name, COUNT(r.id) AS archive_count
FROM archive_category c
LEFT JOIN archive_record r ON r.category_id = c.id
GROUP BY c.id, c.category_name
ORDER BY c.id;
```

2. 每状态申请数：`SELECT application_status, COUNT(*) ... GROUP BY application_status;`。
3. 借阅中清单：先约定学习规则“申请状态 1 表示已批准”，用 `INNER JOIN archive_record r ON a.archive_id = r.id WHERE a.application_status='1'` 查询编号、名称、申请人。
4. 从未申请过的档案：使用 `LEFT JOIN`，最后 `WHERE a.id IS NULL`。逐条在注释里写为什么 ON 是 `a.archive_id = r.id`。
5. 加一条 HAVING：找“档案数大于等于 2”的分类；对比把条件误写进 WHERE 会怎样。
