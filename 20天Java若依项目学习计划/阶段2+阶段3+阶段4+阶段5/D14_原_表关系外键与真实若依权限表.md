> 今日目标：理解一对多、多对多、中间表；能用只读 SQL 看懂若依的“用户—角色—菜单”关系。

## 知识点速记（完成当天任务后复习）

- 一对多：一个分类对应多份档案，外键/关联列放在“多”的档案表 `category_id`。
- 多对多：一个用户可有多个角色，一个角色可分给多个用户，需中间表 `sys_user_role`。
- `sys_role_menu` 把角色和菜单关联，是授权数据来源之一。
- 外键约束由数据库强制“引用值必须存在”；关联字段是设计上的关系，未必已经定义为 FOREIGN KEY。

## 本日重点、易混点与若依对应

中间表至少包含两侧主键，例如 `user_id`、`role_id`。它不是“多余表”：没有它就无法自然记录一个用户的多个角色。档案借阅申请不是中间表，它本身有申请人、原因、状态、时间等独立业务属性；它是一个业务实体。

若依常以逻辑关系和程序校验组织系统，阅读时以项目实际 SQL 为准，不应擅自给 `sys_` 表加外键。外键优点是数据库保证引用完整；代价是写入/删除顺序受限，复杂系统要结合项目规范决定。面试可答：关系数据库里，多对多通常拆成中间表以保存两端关系并可扩展关系属性。

### 15:00–18:00｜运行两条关系查询

1. 先查管理员实际 ID：

```sql
SELECT user_id, user_name, nick_name FROM sys_user WHERE user_name = 'admin';
```

2. 将下面 `1` 改为上一步管理员 user_id，执行“某用户有什么角色”：

```sql
SELECT u.user_name, r.role_id, r.role_name, r.role_key
FROM sys_user u
JOIN sys_user_role ur ON ur.user_id = u.user_id
JOIN sys_role r ON r.role_id = ur.role_id
WHERE u.user_id = 1;
```

3. 选择上一步一个 `role_id`，查询该角色关联的菜单：

```sql
SELECT r.role_name, m.menu_id, m.menu_name, m.perms, m.path
FROM sys_role r
JOIN sys_role_menu rm ON rm.role_id = r.role_id
JOIN sys_menu m ON m.menu_id = rm.menu_id
WHERE r.role_id = 1
ORDER BY m.order_num, m.menu_id;
```

4. 若字段名不匹配，不要猜：用 `SHOW COLUMNS FROM 表名`，将 SQL 字段替换为项目真实字段。
