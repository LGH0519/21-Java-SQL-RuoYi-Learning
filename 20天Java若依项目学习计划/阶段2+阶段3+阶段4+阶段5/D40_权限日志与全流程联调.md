# D40｜权限、日志与前后端全流程联调

> 今日目标：三种角色跑通完整流程，并从 Network、后端日志、DBeaver 三处证明关键操作和越权拒绝。不要自行创建新的权限框架或操作日志表。

## 1. 知识速记

- 菜单/按钮权限与后端 `@PreAuthorize` 同时存在；关键操作使用 `@Log` 进入若依操作日志。
- 全流程：管理员录入分类/档案→员工检索/申请→管理员审批/借出→管理员归还→逾期可查。
- 联调证据三件套：HTTP 请求/响应、后端日志/断点、数据库状态。
- 越权测试是功能验收的一部分，不是可选项。

## 2. 资料

- D22、D30 权限对照；D24 `@Log`；D32 权限矩阵；D34–D39 模块测试证据。
- [若依 Vue：操作日志/权限相关文档](https://doc.ruoyi.vip/ruoyi-vue/)。

## 3. 知识详解

每个业务动作至少有三种看法：前端按钮/接口是否正确发出；Controller/Service 是否通过权限并执行规则；数据库是否准确落表。只看页面“成功”不够，尤其审批/归还是多表状态。越权应返回明确拒绝，不能仅因按钮不可见就算通过。

## 4. 今天照做

### 09:00–12:00｜配置与审查角色

1. 按 D32 权限矩阵在若依角色管理中配置/核查普通员工、档案管理员、系统管理员所需菜单/按钮。
2. 在每个业务 Controller 的新增、删除、申请、撤销、审批、驳回、借出、归还方法，核对 `@PreAuthorize`；关键动作核对 `@Log`。先用表格记录缺失，再让 AI 给最小补丁。
3. 审 diff：权限字符串必须来自矩阵，日志标题/业务类型要能区分审批与归还。

### 15:00–18:00｜跑正向完整流程

1. 管理员：新增虚构分类和档案（含附件可选）。
2. 普通员工：检索该档案、提交申请。
3. 档案管理员：审批通过、确认借出、随后确认归还。
4. 每一步保留：Network 请求/响应、后端日志/断点之一、DBeaver 对应表结果。不要使用真实单位档案或个人信息。

### 19:00–23:00｜越权和日志验收

2. 进入系统操作日志，筛选审批/归还动作，确认操作人、时间、标题与页面动作对应。
3. 建 `D40-integration-test.md`，每条写角色、操作、预期、实际、三处证据。

## 5. AI Agent 操作卡

把权限矩阵、Controller 方法清单和单条 diff 交给 AI，要求只找“缺失/不一致权限、未记录关键日志、越权测试缺口”。人工决定每项角色权限；AI 不拥有修改账户和发布权限。
