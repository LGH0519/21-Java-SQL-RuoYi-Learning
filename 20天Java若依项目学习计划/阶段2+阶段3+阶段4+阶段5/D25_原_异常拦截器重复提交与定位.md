# Day 25：异常、拦截器、重复提交与定位策略

> 今日目标：建立固定排错顺序，不凭感觉改代码；理解全局异常处理与重复提交保护在请求链中的位置。

## 知识点速记（完成当天任务后复习）

- 全局异常处理将未处理异常转换为统一错误响应，方便前端显示和日志定位。
- 拦截器/过滤器可在 Controller 前后执行通用检查；重复提交保护避免短时间重复写入。
- 固定链：页面事件 → Network/Console → Controller → Service → Mapper XML/日志 → DBeaver。
- 401/403 看身份权限；500 看后端异常栈；查询错看参数、动态 SQL、数据。

## 本日重点、易混点与若依对应

前端页面无请求，后端再正确也不会执行；有请求但 404，优先 URL/映射；401/403 是安全边界；500 必须看完整后端异常而非只看弹窗；数据库结果不对时，MyBatis 日志和 DBeaver 同等 SQL 是证据。重复提交保护不是替代唯一约束、事务或幂等设计，它是额外防线。
