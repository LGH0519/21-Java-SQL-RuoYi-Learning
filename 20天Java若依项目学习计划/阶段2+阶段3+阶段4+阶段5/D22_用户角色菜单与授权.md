# D22｜用户、角色、菜单与授权

> 今日目标：从数据库中间表和页面现象双重验证“认证是你是谁，授权是你能做什么”。

## 1. 知识速记

- 认证（Authentication）：确认身份，例如登录成功。
- 授权（Authorization）：基于角色/权限决定可访问的菜单、按钮、接口。
- `sys_user_role`、`sys_role_menu` 是多对多中间表；修改权限应通过若依页面/规范接口，不能手改未知系统数据。
- 菜单隐藏不等于安全，后端 `@PreAuthorize` 也必须拒绝越权请求。

## 2. 资料

- D14 的两条只读 JOIN SQL 与关系图。
- [Spring Security 官方架构概览](https://docs.spring.io/spring-security/reference/servlet/architecture.html)：只读认证/授权概念。

## 3. 知识详解

用户拥有角色，角色关联菜单/权限，前端据此生成可见菜单和按钮；后端同时依据权限注解检查接口访问。测试权限要使用明确命名的测试账号，记录初始状态；绝不动 admin 的默认权限，不创建“所有权限”测试角色。

## 5. AI Agent 操作卡

给 AI 角色矩阵（不含账户/密码），让它检查“谁能看、谁能新增、谁能审批”是否冲突。AI 不可替你创建角色、更改 admin、分配单位实际权限。
