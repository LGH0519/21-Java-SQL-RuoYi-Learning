# D38｜审批、借出登记与事务

> 今日目标：实现档案管理员批准/驳回。批准必须在一个事务中完成“申请批准、创建借阅记录、档案变借阅中”。

## 1. 知识速记

- 批准前置：申请已提交、档案可借阅、操作者有审批权限。
- 批准副作用：申请状态→已批准；新增借阅记录；档案状态→借阅中。
- 三步必须 `@Transactional`：任一步失败就回滚，不能留下批准申请却没有借阅记录的半成品。
- 驳回只改变申请状态并记录审批意见（若字段已设计）。

## 2. 资料

- D15 事务实验，D21 `@Transactional`，D32 状态图。
- Spring 官方事务概念：[Transaction Management](https://docs.spring.io/spring-framework/reference/data-access/transaction.html)。

## 3. 知识详解

审批不是修改一个 status 的 CRUD：它是跨表业务命令。事务边界应包住完整 Service 方法而非 Controller。并发时两个管理员同时批准同一申请/档案是高级边界；V1 先通过“状态前置条件 + 影响行/再次校验”防止明显重复，后续可完善乐观锁/锁策略。

## 6. 验收与文末答案

- [ ] 管理员可批准/驳回，员工被后端拒绝审批。
- [ ] 批准后三张表一致。
- [ ] 人为可控失败时无半成品。

答案：为何只给申请表加 `@Transactional` 不够？事务必须覆盖同一业务中对申请、借阅记录、档案的全部写入；否则可能出现数据不一致。
