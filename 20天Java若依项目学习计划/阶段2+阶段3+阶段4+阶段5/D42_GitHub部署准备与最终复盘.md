## 1. 知识速记

- 提交前检查：`.gitignore`、配置示例、SQL、README、截图、Git diff、秘密扫描。
- 绝不提交：密码、Token、真实附件、私有地址、用户数据、IDE 临时文件、构建产物（按项目规则）。

- 本地可复现是部署前提；服务器部署另需单位授权、网络/安全/运维流程。

## 3. 知识详解

“推送 GitHub”是外部发布动作：先确认仓库可见性、单位代码规范、若依许可证/开源说明和是否包含敏感内容。没有用户明确的仓库地址/授权时，不擅自新建或推送远程仓库；本日可把本地仓库准备到可推送状态。部署也不是复制文件：数据库、Redis、后端、前端、上传目录和配置都要对应。

## 4. 今天照做

### 09:00–12:00｜安全预检

1. 终端进入 `E:\WorkSpace\ruoyi-archive-management`，执行 `git status`、`git diff --stat`、`git diff --check`。
2. 打开 `.gitignore`，确认本地配置、日志、IDE 文件、上传测试文件不被意外跟踪；只添加与你实际发现的敏感/临时路径，不做无关大改。
3. 用 `git grep -n -i "password\|token\|secret"` 检查**已跟踪文本**的可疑位置；结果可能含示例字段，逐条人工判断，绝不把输出中可能的值发到外部。
4. 确认 SQL 仅含虚构测试数据，截图已脱敏。

### 15:00–18:00｜本地构建与复现

1. 依 README 从头核对：MySQL 初始化、Redis 启动、后端 Maven 构建/运行、前端依赖安装/运行。依项目现有脚本执行，不升级依赖。
2. 后端构建前先确认所在模块和 README 指令；构建成功后记录 jar 的实际输出路径。前端按 package.json 的实际 scripts 执行构建，记录 dist 输出路径。
3. 关闭后再按 README 重启前后端，完成登录/字典/档案核心流程的最小 smoke test。
4. 若构建失败，保留完整错误和复现命令，按 D25 定位；不要删 lock 文件、全局升级或让 AI 大范围替换依赖。

### 19:00–23:00｜GitHub 前准备与复盘

1. 在 `docs\deployment\local-deploy.md` 写：前置版本、配置占位、建库命令、启动命令、端口、健康检查 URL、常见失败排查；不写任何真实密码。
2. 若你已有明确 GitHub 仓库并授权推送：确认远程 URL、`git status` 只含本项目文件，再按 `git add`→`git commit`→`git push` 执行。若未提供仓库/授权，只完成本地提交与待推送清单。
3. 写最终复盘：最强的三项能力、三个待补项、第二版候选（多级审批、全文检索、跨部门调阅），明确不在 V1 实现。
