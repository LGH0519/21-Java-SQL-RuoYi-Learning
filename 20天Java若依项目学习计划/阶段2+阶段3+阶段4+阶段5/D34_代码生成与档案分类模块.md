# D34｜代码生成与档案分类模块

> 今日目标：用若依生成器完成已审查的分类 CRUD，并用“页面—API—Controller—Service—Mapper—数据库”六处证据验证。最终业务代码仅由生成器/AI 产出。

## 1. 知识速记

- 生成前检查：表名/注释、主键、字段类型、查询字段、表单字段、权限/菜单、输出模块路径。
- 分类可支持树形 `parent_id`；V1 首先保证增删改查和父子关系不自相矛盾。
- 生成后必须审查 Git diff、编译、启动、Network、DBeaver，不能只看页面。

## 2. 资料

- D26 生成器预览笔记。
- [若依 Vue：代码生成](https://doc.ruoyi.vip/ruoyi-vue/document/htsc.html)。

## 3. 知识详解

生成器的字段配置就是低代码设计输入：`category_name` 应是文本和查询条件，`parent_id` 是关联选择，`status` 是字典/单选状态。树形删除需防止“有子分类仍删除”；若生成器不提供完整规则，AI 先给 Service 规则和测试，再生成最小补丁。

## 4. 今天照做

### 09:00–12:00｜生成前审查

1. DBeaver 打开 `archive_management_v1.archive_category`，核对字段字典、注释、主键和 `parent_id`。
2. 在 `docs\design\generator-check-category.md` 填：表、功能名、包/模块目标、查询字段、表单字段、权限前缀 `archive:category`、菜单名称。
3. 让 AI 仅复核此清单并列出生成风险；自行决定是否修 SQL，再执行/复核。

### 15:00–18:00｜生成并受控集成

1. 若依后台 → 系统工具 → 代码生成 → 导入 `archive_category` → 编辑字段配置 → 预览。逐文件确认生成位置。
2. 下载/生成到隔离目录，先查看，不覆盖项目现有文件。
3. 在 Git 工作区执行 `git status`，确认没有无关改动；按项目模块结构把生成文件集成。若生成器提供“生成到本地”功能，目标路径必须是当前项目且先确认预览。
4. 每次文件复制后立即 `git diff --stat`；发现无关大面积改动立刻停下，不用 reset --hard。

### 19:00–23:00｜六处验证

1. 后端编译/启动，前端启动；新增分类、编辑名称、查询、删除一条无子级临时分类。
2. F12 Network 找 list/add/edit/remove 请求；IDEA 断点进 Controller；DBeaver 核对表数据。
3. 对“删除有子分类”写一个测试：预期拒绝或按已确认规则处理，不能悄悄级联删除。
4. 保存 `D34-test-evidence.md`：操作、预期、实际、证据链接/截图。

## 5. AI Agent 操作卡

输入仅限已审查的字段字典、生成前检查表和单个生成文件 diff。先让 AI 列“字段映射、查询/表单、权限、树形删除”四类风险；确认后才生成最小补丁。每次补丁后检查 Git diff、编译、页面/API/DBeaver，不允许 AI 修改模板、依赖或执行 Git 重置。
