# Day 23：登录、JWT 与 Security 过滤器链

> 今日目标：不要求背完安全源码，但能画出登录获得 Token、后续请求携带 Token、过滤器识别身份、权限注解放行/拒绝的链路。

## 知识点速记（完成当天任务后复习）

- 登录接口验证账号密码，成功后返回访问凭据（Token）。
- JWT 是携带身份相关声明的一种令牌格式；它不是“加密后的密码”。
- 后续请求通常在 `Authorization` 请求头带 Token；过滤器先解析/验证，再将认证信息放入安全上下文。
- `@PreAuthorize` 在访问业务接口前检查权限。

## 视频、文档与若依对应点

- [JWT 官方介绍](https://jwt.io/introduction)：只看 JWT 是什么与组成概念。
- 本机按搜索实际类名打开：`SysLoginController`、`SysLoginService`、`TokenService`、`JwtAuthenticationTokenFilter`。

## 本日重点、易混点与若依对应

登录请求与业务请求不是同一件事：登录请求用于建立身份；列表请求带凭据用于证明身份。Token 是敏感凭据，截图、导出 cURL、提交 Git 时必须遮挡/删除。401 常是未认证/令牌无效，403 常是已认证但无权限；仍要以项目响应和日志为准。
