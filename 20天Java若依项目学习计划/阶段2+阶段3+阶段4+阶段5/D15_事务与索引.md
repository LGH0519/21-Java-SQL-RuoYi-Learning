# D15｜事务与索引

> 今日目标：亲手完成一次 COMMIT、一次 ROLLBACK；为档案第一版说明“为什么加这个索引”，而不是给每列都加索引。

## 1. 知识速记

- 事务把多个写操作作为一个整体：都成功才提交，否则回滚。
- ACID：原子性、一致性、隔离性、持久性。当前重点是原子性：不能只写成功一半。
- `START TRANSACTION` 开始；`COMMIT` 永久提交；`ROLLBACK` 撤销本事务未提交改动。
- 索引帮助定位数据；代价是占空间、INSERT/UPDATE/DELETE 要维护索引。
- 唯一索引同时提供查询能力和“不可重复”的规则；复合索引的列顺序需贴合查询条件。

## 3. 知识详解

批准借阅至少涉及：申请变为已批准、写一条借阅记录、档案变为借阅中。这三步任何一步失败，都不能让其余两步留下半成品，后续 Day38 用 Spring `@Transactional` 实现同一原则。索引不是越多越好：低区分度的 `status` 单列索引常收益有限；若常按“状态 + 到期日”筛选逾期，`(status, due_date)` 这样的复合索引才更贴合查询。

易混点：事务回滚只能撤销同一事务中尚未提交的修改；已 COMMIT 的数据不能靠 ROLLBACK 找回。索引并不保证业务状态合法，状态流转仍由 Service 规则控制。

### 09:00–12:00｜事务成功用例

1. 新建脚本 `day15_transaction_index.sql`，执行 `USE archive_learning;`。
2. 执行下面 SQL，并在每一步后 SELECT 观察：

```sql
START TRANSACTION;
INSERT INTO archive_borrow_application
  (archive_id, applicant_name, apply_reason, application_status)
VALUES (1, '事务测试员', '验证提交', '0');
UPDATE archive_record SET status = '1' WHERE id = 1;
```

3. 记录：COMMIT 后两项都看得见，说明本次写入已提交。

### 15:00–18:00｜回滚失败用例

1. 先选一个未借阅档案 ID，例如 `2`；执行：

```sql
START TRANSACTION;
INSERT INTO archive_borrow_application
  (archive_id, applicant_name, apply_reason, application_status)
VALUES (2, '回滚测试员', '验证回滚', '0');
UPDATE archive_record SET status = '1' WHERE id = 2;
ROLLBACK;

SELECT archive_no, status FROM archive_record WHERE id = 2;
SELECT * FROM archive_borrow_application WHERE applicant_name = '回滚测试员';
```

2. 预期：档案状态仍为开始前值，回滚测试员申请不存在。若不符合，先检查是否在同一编辑器/连接执行、是否中途自动提交，再在学习库重新试验。
3. 不要用故意写错表名冒充事务失败；本日重点是先明确执行 ROLLBACK 的效果。
