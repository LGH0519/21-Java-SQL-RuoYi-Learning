# Day 24：Redis、字典缓存与操作日志

> 今日目标：知道 Redis 在若依字典功能中缓存什么、刷新缓存解决什么，并能找到 `@Log` 生成的系统操作记录。

## 知识点速记（完成当天任务后复习）

- Redis 是内存型键值存储；本项目可用于缓存、会话/Token 相关数据等，今日只研究字典缓存。
- 缓存目的：减少重复数据库查询；代价：数据更新后可能需要刷新以避免旧值。
- `@Log` 用于记录关键操作的审计信息；操作日志不是业务表的替代品。

## 视频、文档与若依对应点

- [Redis 官方文档](https://redis.io/docs/latest/)：只读“data types”总览，不做安装/清空操作。
- `SysDictTypeServiceImpl.java` 中搜索 `init`、`loadingDictCache`、`selectDictDataByType`。
- `SysDictTypeController.java` 中搜索 `@Log`。

## 本日重点、易混点与若依对应

缓存命中时可以不访问数据库；缓存为空或刷新后会重新加载。不要把“看不到立即更新”直接判断为数据库没改：依次区分页面缓存、接口响应、Redis 缓存、MySQL 数据。Redis 中键可能被多个功能使用，初学者绝不执行 `FLUSHALL`、`DEL` 未知 key。
