##  初次登录一共 3 次请求，不是 2 次

### 完整请求流程

```
┌─────────────────────────────────────────────────────────────────┐
│                    前端（Vue）                    后端（Java）    │
└─────────────────────────────────────────────────────────────────┘

请求①  POST  /login                              ← 登录
  ├─ 前端发送：{ username, password, code, uuid }
  ├─ 后端：SysLoginController.login()
  ├─ 后端：SysLoginService.login()  → 验证用户名密码
  ├─ 后端：TokenService.createToken() → 生成 JWT
  └─ 返回：{ code: 200, token: "eyJhbG..." }
        ↓ 前端拿到 token，存入 localStorage
        ↓

请求②  GET  /getInfo         ← 获取用户信息（需要 token）
  ├─ 前端自动发送：Authorization: Bearer <token>
  ├─ 后端：JwtAuthenticationTokenFilter 验证 token
  ├─ 后端：SysLoginController.getInfo()
  ├─ 后端：SecurityUtils.getLoginUser() → 从 Redis 获取用户
  ├─ 后端：permissionService.getRolePermission() → 角色
  ├─ 后端：permissionService.getMenuPermission() → 权限
  └─ 返回：{ user, roles, permissions, ... }
        ↓

请求③  GET  /getRouters      ← 获取路由菜单（需要 token）
  ├─ 前端自动发送：Authorization: Bearer <token>
  ├─ 后端：JwtAuthenticationTokenFilter 验证 token
  ├─ 后端：SysLoginController.getRouters()
  ├─ 后端：menuService.selectMenuTreeByUserId() → 查询菜单树
  └─ 返回：{ menus: [...] }  → 前端据此生成侧边栏菜单
```

---

### 📊 请求汇总

| 次数 | 方法 | 路径 | 是否需要 Token | 作用 |
|-----|------|------|--------------|------|
| ① | POST | `/login` | ❌ 不需要 | 登录，获取 token |
| ② | GET | `/getInfo` | ✅ 需要 | 获取用户信息、角色、权限 |
| ③ | GET | `/getRouters` | ✅ 需要 | 获取菜单路由，生成侧边栏 |

---

### 🔍 代码证据

**请求①** — `SysLoginController.java` 第 56-65 行：
```java
@PostMapping("/login")
public AjaxResult login(@RequestBody LoginBody loginBody)
{
    String token = loginService.login(...);
    ajax.put(Constants.TOKEN, token);  // 返回 token
    return ajax;
}
```

**请求②** — `SysLoginController.java` 第 72-94 行：
```java
@GetMapping("getInfo")
public AjaxResult getInfo()
{
    LoginUser loginUser = SecurityUtils.getLoginUser();  // ← 需要 token 才能获取
    SysUser user = loginUser.getUser();
    Set<String> roles = permissionService.getRolePermission(user);
    Set<String> permissions = permissionService.getMenuPermission(user);
    // 返回 user, roles, permissions...
}
```

**请求③** — `SysLoginController.java` 第 101-107 行：
```java
@GetMapping("getRouters")
public AjaxResult getRouters()
{
    Long userId = SecurityUtils.getUserId();  // ← 需要 token 才能获取
    List<SysMenu> menus = menuService.selectMenuTreeByUserId(userId);
    return AjaxResult.success(menuService.buildMenus(menus));
}
```

### 💡 为什么需要 3 次请求？

**生活化类比：进公司上班**

```
① 刷门禁卡（POST /login）
   └─ 证明你是公司员工 → 拿到工牌（token）

② 查人事档案（GET /getInfo）
   └─ 查看你的部门、职级、权限 → 决定你能进哪些区域

③ 拿楼层地图（GET /getRouters）
   └─ 查看公司有哪些部门/房间 → 生成导航菜单
```

**如果只有 2 次请求会怎样？**

| 场景 | 缺少什么 | 后果 |
|-----|---------|------|
| 只有 ① | 没有用户信息和权限 | 前端不知道显示什么菜单 |
| 只有 ①② | 没有路由信息 | 知道权限但不知道菜单结构 |
| 只有 ①③ | 没有用户信息 | 知道菜单但不知道当前用户 |
| **①② 都有** | ✅ 完整 | 知道用户是谁、能干什么、显示什么菜单 |

### ⚠️ 可能的误解

如果你在前端网络面板（F12）只看到 **2 次请求**，可能的原因：

1. **请求②和③并发执行**：前端可能同时发 GET /getInfo 和 GET /getRouters，看起来像一次
2. **刷新页面时**：token 已存在，可能只触发 ②③，不触发 ①
3. **前端缓存**：某些情况下前端会复用之前的数据

但**后端代码层面**，初次登录一定是 **3 次请求**：
- `POST /login` → 1 次
- `GET /getInfo` → 1 次  
- `GET /getRouters` → 1 次

---

### ✅ 总结

> **初次登录一共 3 次请求，不是 2 次。**
> 
> 1. `POST /login` — 登录获取 token
> 2. `GET /getInfo` — 获取用户信息和权限
> 3. `GET /getRouters` — 获取菜单路由

如果你在前端只看到 2 次，可能是 ②③ 并发执行被合并显示了，或者你看到的是**刷新页面**（已有 token，只需 ②③ 两次）。
