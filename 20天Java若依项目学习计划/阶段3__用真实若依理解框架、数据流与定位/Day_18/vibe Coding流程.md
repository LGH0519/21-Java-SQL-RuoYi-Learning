```
若依后台管理系统
├─ 后端：Spring Boot
```

这种项目不适合重新搭建架构，也暂时不建议使用 `sites-building`。核心策略应该是：保留若依的基础设施，逐个裁剪业务模块，每次裁剪后都验证登录、权限、菜单和构建流程。

## 需要先确认若依版本

不同版本的目录、技术栈和裁剪方法差异很大，例如：

- `RuoYi-Vue`：通常是 Vue 2 + Spring Boot 前后端分离
- `RuoYi-Vue3`：Vue 3
- `RuoYi-Vue-Plus`：社区增强版本
- `RuoYi-Cloud`：Spring Cloud 微服务版本
- 传统 `RuoYi`：可能是 Thymeleaf 单体版本

请告诉我你具体使用的是哪一个版本；如果不确定，可以把项目目录交给我分析，我会通过 `pom.xml`、`package.json` 和目录结构判断。

## 最适合你的辅助工具

### Codex：项目分析和编码主力

Codex可以负责：

- 读取整个若依项目结构
- 解释各模块用途
- 分析模块之间的 Maven、Java、菜单和数据库依赖
- 制定裁剪顺序
- 按若依现有风格增加 Controller、Service、Mapper 和 Vue 页面
- 执行前后端构建与测试
- 审查每次修改

建议第一条任务这样下达：

> 分析这个若依项目的前端、后端和数据库结构。列出每个模块的用途及依赖关系，区分“必须保留”“可选保留”“可以裁剪”。现在只分析，不修改代码。

### Git：必须使用

裁剪代码非常容易误删依赖，开始前应该建立 Git 基线：

```
main                 原始可运行版本
feature/project-base 裁剪后的项目基础版本
feature/xxx           每个新功能单独开发
```

每次只裁剪一个模块并提交。出现问题时可以准确比较，而不需要猜哪些文件改坏了。

### IntelliJ IDEA

主要用于：

- Spring Boot 开发
- Maven 依赖查看
- Java 调试
- 查找接口、类和方法引用
- 查看 MyBatis XML
- 启动后端服务

### VS Code 或 WebStorm

主要用于：

- Vue 页面开发
- 路由和状态管理分析
- ESLint 检查
- 前端调试

如果你不想同时学习两个 IDE，也可以全部使用 IntelliJ IDEA。

### DBeaver 或 Navicat

主要用于：

- 查看 MySQL 表结构
- 执行若依初始化 SQL
- 检查菜单、角色和权限数据
- 查看业务数据
- 导出数据库备份

新手优先推荐 DBeaver，因为免费并且功能足够。

### Apifox 或 Postman

主要用于：

- 单独测试后端接口
- 区分问题出在前端还是后端
- 保存接口参数和响应示例
- 测试 Token、权限和异常输入

如果主要使用中文界面，可以选择 Apifox。

### `computer-use` Skill

在前后端启动后使用，用于：

- 自动操作登录页面
- 测试菜单和按钮权限
- 完整验证新增、查询、修改、删除流程
- 检查裁剪后有没有失效页面
- 复现界面操作导致的错误

例如：

> 使用 computer-use 登录系统，遍历所有可见菜单，记录打不开的页面和浏览器控制台错误。

### Figma 插件：有设计稿时再安装

只有以下情况需要：

- 已经有 Figma 页面设计
- 需要根据设计稿实现 Vue 页面
- 需要对照设计稿检查尺寸、颜色和布局

普通若依表格、表单页面不需要安装。

### Codex Security 插件：上线前使用

适合检查：

- 越权访问
- 未授权接口
- SQL 注入风险
- 文件上传风险
- 敏感信息泄漏
- 默认账户和弱密码
- 前后端权限只做了一边的问题

它应该在业务基本完成后使用，不能代替日常测试。

### `skill-creator`：流程稳定后使用

可以为你的若依项目创建专属 Skill，固定以下规则：

- 新功能必须匹配现有目录和编码风格
- 接口必须检查权限注解
- 数据库变更必须提供独立 SQL
- 删除模块前必须搜索前后端和数据库引用
- 修改后必须执行后端测试、前端构建和页面验证
- 不重构无关代码

第一阶段不用急着创建，等分析完项目结构后再做会更准确。

## 若依项目的推荐执行顺序

### 1. 建立可运行基线

成功标准：

- MySQL 初始化完成
- 后端启动成功
- 前端启动成功
- 可以正常登录
- 菜单、验证码和权限功能正常

在基线没有跑通前，不进行裁剪。

### 2. 生成架构分析报告

重点分析：

```
后端 Maven 模块
Java 包和分层
前端目录和路由
权限认证流程
菜单加载流程
MyBatis 映射
数据库表
定时任务
代码生成器
文件上传
日志和监控
```

输出每个模块的依赖关系和裁剪风险。

### 3. 给模块分类

建议分为三类：

|分类|示例|
|---|---|
|必须保留|登录认证、用户、角色、菜单、权限、公共模块|
|根据需求决定|部门、岗位、字典、参数、通知公告|
|通常可以裁剪|演示页面、在线用户、定时任务、代码生成器、监控模块|

这只是常见分类，最终必须以你的业务需求和具体若依版本为准。

### 4. 分批裁剪

一个批次只删除一个相对独立的模块，同时检查：

- 后端 Java 类
- Maven 依赖
- 前端 API
- Vue 页面
- 路由和菜单
- 权限标识
- MySQL 菜单数据
- 关联数据库表
- 定时任务和配置文件

每批验证：

```
后端能够编译并启动
前端能够构建
系统能够登录
菜单加载正常
浏览器控制台无新增错误
```

不要一次性删除所有“不需要”的目录。

### 5. 添加业务功能

每个功能按同一套顺序实现：

```
需求和验收标准
→ 数据库表设计
→ SQL迁移
→ Entity/Domain
→ Mapper
→ Service
→ Controller
→ 权限标识
→ 前端API
→ Vue页面
→ 菜单和按钮权限
→ 前后端联调
→ 自动化验证
```

### 6. 上线前检查

至少包括：

- 前后端生产构建
- 数据库备份和迁移测试
- 普通用户越权测试
- 文件上传测试
- 重复提交和非法参数测试
- 日志中是否泄露密码或 Token
- 配置文件是否包含真实密码
- 新环境部署说明

当前最重要的一步不是安装插件，而是确认若依版本并把项目放入当前工作区。之后我可以先输出完整的模块依赖和裁剪清单，全程不改代码，等你确认后再逐项实施。
