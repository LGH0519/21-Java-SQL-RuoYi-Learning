## HTTP 方法与"数据流向"的对应关系

| HTTP 方法  | 数据方向             | 典型用途      | 类比           |
| -------- | ---------------- | --------- | ------------ |
| `GET`    | **后端 → 前端**（拿数据） | 查询列表、获取详情 | 去图书馆**借书**   |
| `POST`   | **前端 → 后端**（送数据） | 新增、提交表单   | 去图书馆**捐书**   |
| `PUT`    | **前端 → 后端**（送数据） | 修改、更新     | 去图书馆**替换旧书** |
| `DELETE` | **前端 → 后端**（送指令） | 删除        | 去图书馆**申请下架** |

## 那"把前端数据传到后端"的接口长什么样？

真正**发送数据到后端**的接口，通常具备以下特征：
- `method` 是 `'post'` 或 `'put'` 或 `'delete'`
- 带有 `data` 或 `params` 参数

**举例**（以用户管理为例，实际代码在 `src/api/system/user.js` 中）：

```js
// 新增用户 —— 这才是"把前端数据传到后端"
export function addUser(data) {
  return request({
    url: '/system/user',
    method: 'post',     // ← post：提交数据
    data: data          // ← data：要传给后端的数据
  })
}

// 修改用户
export function updateUser(data) {
  return request({
    url: '/system/user',
    method: 'put',
    data: data
  })
}

// 删除用户
export function delUser(userId) {
  return request({
    url: '/system/user/' + userId,
    method: 'delete'
  })
}
```

### 看清楚这段代码

```js
export const getRouters = () => {
  return request({
    url: '/getRouters',
    method: 'get'    // ← 关键：method 是 get
  })
}
```

| 配置项 | 值 | 含义 |
|--------|-----|------|
| `url` | `'/getRouters'` | 请求的路径地址 |
| `method` | `'get'` | 请求方式 |

**`get` 方法 = "我去拿数据"，不是"我把数据送过去"。**

这个接口的真实作用是：**前端向后端说"请把菜单路由数据给我"**，后端返回菜单列表，前端用来动态生成左侧导航栏。

### 异常处理的完整流程

异常信息传递的框架与正常数据一样，但后端返回的是"错误码 + 错误信息"，前端会拦截并显示错误提示。

1. 用户在登录页输入用户名和密码，点击登录
        ↓
2. 前端发起 POST 请求到 /dev-api/login
        ↓
3. Vite 代理转发 → 后端 /login
        ↓
4. 后端校验密码，发现密码错误
        ↓
5. 后端返回响应：{ code: 500, msg: "用户名或密码错误" }
        ↓
6. 前端"响应拦截器"拦截到这个响应
        ↓
7. 拦截器识别出 code=500，弹出错误提示：
   "用户名或密码错误"
        ↓
8. 用户看到红色错误提示，登录失败


异常处理本质上和正常数据走同一套流程（请求 → 代理 → 后端 → 响应），区别在于：

**成功时：后端返回 { code: 200, data: {...} }，前端拿到数据正常渲染**

**异常时：后端返回 { code: 500, msg: "错误信息" }，前端拦截器识别错误码，自动弹出对应的错误提示**
