**过滤器（Filter）先执行，DispatcherServlet 后执行。**

---

## 请求处理顺序

```
HTTP 请求进入
       ↓
┌─────────────────────────────────┐
│  Filter 链（按注册顺序依次执行）    │  ←  先执行
│  ┌───────────────────────────┐  │
│  │ 1. RepeatableFilter       │  │
│  │ 2. XssFilter              │  │
│  │ 3. JwtAuthenticationTokenFilter │  ← 验证 Token
│  │ ... 其他 Filter           │  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘
       ↓
┌─────────────────────────────────┐
│  DispatcherServlet               │  ← ② 后执行
│  （分发到对应的 Controller）       │
└─────────────────────────────────┘
       ↓
Controller → Service → DAO
```

---

## 用生活化类比

> 想象去**银行办业务**：
> 
> **Filter 链 = 银行门口的安检 + 取号机**
> - 保安检查你的身份证（JwtAuthenticationTokenFilter 验证 Token）
> - 没身份证？直接拦住，不让进
> - 有身份证？放行，去取号
> 
> **DispatcherServlet = 大厅的业务引导员**
> - 你拿着号（请求），引导员看你要办什么业务
> - 把你带到对应的窗口（Controller）

**安检（Filter）肯定在引导员（DispatcherServlet）之前！**

## 关键代码解读

### SecurityConfig.java 第 113-116 行：
```java
// 添加 JWT filter
.addFilterBefore(authenticationTokenFilter, UsernamePasswordAuthenticationFilter.class)
// 添加 CORS filter
.addFilterBefore(corsFilter, JwtAuthenticationTokenFilter.class)
.addFilterBefore(corsFilter, LogoutFilter.class)
```

`addFilterBefore(A, B)` 的意思是：**A 在 B 之前执行**

所以顺序是：
- `CorsFilter` 在 `JwtAuthenticationTokenFilter` 之前
- `JwtAuthenticationTokenFilter` 在 `UsernamePasswordAuthenticationFilter` 之前

### FilterConfig.java 第 44、61、76 行：
```java
registration.setOrder(FilterRegistrationBean.HIGHEST_PRECEDENCE);  // XssFilter、RefererFilter 最高优先级
registration.setOrder(FilterRegistrationBean.LOWEST_PRECEDENCE);   // RepeatableFilter 最低优先级
```

## 用生活化类比

> 想象去**机场登机**：
> 
> | 顺序 | 过滤器 | 类比 |
> |------|--------|------|
> |  | CorsFilter | 机场大门（检查你是否来自允许的地区） |
> |  | XssFilter | 安检仪（检查行李有没有危险品） |
> | ③ | RefererFilter | 核对机票来源（检查你是不是正规渠道买的票） |
> | ④ | **JwtAuthenticationTokenFilter** | **登机口验票（检查你的 Token/登机牌）** |
> | ⑤ | RepeatableFilter | 复印机票（让请求体可以多次读取） |
> | ⑥ | **DispatcherServlet** | **登机后找座位（分发到对应的 Controller）** |

**验票（Token 验证）肯定在找座位（DispatcherServlet 分发）之前！**

## 总结

| 问题 | 答案 |
|------|------|
| Filter 和 DispatcherServlet 谁先执行？ | **Filter 先执行** |
| Token 验证在哪里？ | 在 Filter 链中（`JwtAuthenticationTokenFilter`） |
| Token 验证失败会怎样？ | 直接返回 401，**不会到达 DispatcherServlet** |
| DispatcherServlet 什么时候执行？ | 所有 Filter 都通过后，才执行 |

**一句话**：请求先经过 Filter 链（包括 Token 验证），全部通过后才会到达 DispatcherServlet 进行业务分发。
