## 🎯 核心概念澄清（先纠正常见误解）

### ❌ 常见误解

> "前端拦截器拦截后端发上来的信息"  
> "后端过滤器过滤前端下来的信息"

### ✅ 正确理解

**拦截器和过滤器不是"互相拦截"的关系，而是各自在自己的方向上工作：**

```
前端拦截器 ←→ 后端过滤器
    ↓              ↓
  发请求时拦截    收请求时过滤
  收响应时拦截    发响应时过滤
```

## 📋 二、前端拦截器详解

### 位置：Axios 请求/响应拦截器

```javascript
// request.js

// ===== 请求拦截器（发请求前执行）=====
axios.interceptors.request.use(
  config => {
    // 🎯 拦截：在请求发出前"抓住"它，做处理
    
    // 1. 从 localStorage 取 token
    const token = getToken();
    
    // 2. 自动添加到请求头
    if (token) {
      config.headers['Authorization'] = 'Bearer ' + token;
    }
    
    // 3. 可以加 loading 提示
    // showLoading();
    
    return config;  // 放行，继续发送请求
  },
  error => {
    // 请求出错时处理
    return Promise.reject(error);
  }
);

// ===== 响应拦截器（收到响应后执行）=====
axios.interceptors.response.use(
  response => {
    // 🎯 拦截：在数据交给业务代码前"抓住"它，做处理
    
    const res = response.data;
    
    // 1. 统一处理后端返回的 code
    if (res.code === 200) {
      return res;  // 正常，返回数据
    } else {
      // 2. 错误提示
      Message.error(res.msg);
      return Promise.reject(new Error(res.msg));
    }
  },
  error => {
    // 🎯 拦截：网络错误或后端返回异常时处理
    
    if (error.response) {
      const data = error.response.data;
      
      // 3. Token 过期 → 跳转登录页
      if (data.code === 401) {
        // 清除 token
        removeToken();
        // 跳转到登录页
        router.push('/login');
      }
    }
    
    return Promise.reject(error);
  }
);
```

### 拦截器做了什么？

| 拦截器类型 | 时机 | 作用 | 生活化类比 |
|-----------|------|------|-----------|
| **请求拦截器** | 发请求**前** | 自动加 token、加 loading | 出门前**检查带没带身份证** |
| **响应拦截器** | 收响应**后** | 统一错误处理、token 过期跳转 | 进门后**保安检查身份证** |

## 📋 三、后端过滤器详解

### 位置：Spring 的 Filter Chain（过滤器链）

```
请求进入后端 → 依次经过多个过滤器 → 到达 Controller
响应离开后端 → 依次经过多个过滤器 → 到达前端
```

### 若依项目中的过滤器链（按顺序）

```
HTTP 请求进入
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│  Filter Chain（过滤器链）                                │
│                                                          │
│  ① CorsFilter                                          │
│     ├─ 作用：处理跨域请求                                │
│     ├─ 允许前端域名（localhost:80）访问                   │
│     └─ 添加 CORS 响应头（Access-Control-Allow-Origin）   │
│                                                          │
│  ② XssFilter                                           │
│     ├─ 作用：XSS 跨站脚本攻击防护                        │
│     ├─ 过滤请求参数中的 <script>、javascript: 等        │
│     └─ 替换危险字符为安全字符                            │
│                                                          │
│  ③ RepeatableFilter                                    │
│     ├─ 作用：防止重复提交                                │
│     ├─ 用 Redis 记录已提交的请求                         │
│     └─ 相同请求在 3 秒内只执行一次                       │
│                                                          │
│  ④ RepeatedlyRequestWrapper                            │
│     ├─ 作用：包装 HttpServletRequest                    │
│     └─ 实现重复请求检测逻辑                              │
│                                                          │
│  ⑤ JwtAuthenticationTokenFilter  ←── 最关键！           │
│     ├─ 从 Authorization 头提取 token                     │
│     ├─ 解析 JWT，验证签名和有效期                        │
│     ├─ 从 Redis 获取用户信息                             │
│     ├─ 设置到 SecurityContext                            │
│     └─ 没有 token 或 token 无效 → 返回 401               │
│                                                          │
│  ⑥ OncePerRequestFilter (其他安全过滤器)                │
│     └─ Spring Security 内部过滤器                      │
│                                                          │
└─────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│  Controller 层                                          │
│  SysUserController.list()                               │
│  SecurityUtils.getUsername()  ← 直接使用当前用户           │
└─────────────────────────────────────────────────────────┘
    │
    ▼
  返回 JSON 响应
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│  响应过滤器（与请求过滤器对称）                           │
│                                                          │
│  响应从 Controller 返回                                  │
│  → 经过过滤器链（反向）                                   │
│  → CorsFilter 添加跨域响应头                             │
│  → 返回前端                                             │
└─────────────────────────────────────────────────────────┘
```

## 🎯 四、关键对比

### 拦截器 vs 过滤器

| 维度 | 前端拦截器（Axios） | 后端过滤器（Spring Filter） |
|-----|-------------------|--------------------------|
| **位置** | 浏览器（前端代码） | 服务器（Java 代码） |
| **生命周期** | 请求/响应都在前端处理 | 请求/响应都在后端处理 |
| **能看到什么** | 能看到完整的 HTTP 请求和响应 | 能看到完整的 HTTP 请求和响应 |
| **主要作用** | 自动加 token、统一错误处理 | 安全过滤、跨域、权限验证 |
| **能否修改请求体** | ✅ 可以（如加 header） | ✅ 可以（如包装 request） |
| **能否修改响应体** | ✅ 可以（如统一封装） | ⚠️ 有限（需要包装 response） |

   │
   ▼
⑩ 前台检查（响应拦截器）

## ✅ 核心要点总结

### 1. 拦截器和过滤器不是"互相拦截"

```
前端拦截器 ←→ 后端过滤器
    ↓              ↓
  各自在自己的    各自在自己的
  方向上工作       方向上工作
```

### 2. 它们能看到什么

| 组件 | 能看到请求 | 能看到响应 | 能修改请求 | 能修改响应 |
|-----|----------|----------|----------|----------|
| **前端请求拦截器** | ✅ 能 | ❌ 不能 | ✅ 能（加 header） | ❌ 不能 |
| **前端响应拦截器** | ❌ 不能 | ✅ 能 | ❌ 不能 | ✅ 能（统一封装） |
| **后端过滤器** | ✅ 能 | ✅ 能 | ✅ 能（包装 request） | ⚠️ 有限 |

### 3. 整个流程一句话总结

> **前端拦截器在"出门前"自动帮你贴好身份证（加 token），后端过滤器在"进门时"检查你的身份证（验证 token），两者配合实现免密访问。**

这就是若依前后端分离项目的安全认证完整流程！🎉
