```
# 代码/文档深度解析指令

请对以下文件（或工程）进行完整、详尽、通俗易懂的解析，生成一份结构化的解析文档。

## 解析对象

- 类型：`[单文件 / 多文件 / 整个工程]`（三选一）
- 路径：`[在此填写文件路径或工程根目录路径]`
- 语言/格式：`[如 Java / XML / YAML / Vue / SQL / 自动识别]`（可选，不填则自动识别）

## 输出要求

请严格按照以下六个维度输出，一次性生成完整文档，无需我追问：

---

### 维度一：前置知识术语表

在文档开头提供一份术语表，列出贯穿全文的所有关键技术概念。
- 对每个术语给出：术语名称 → 英文全称（如有）→ 通俗解释 → 生活类比
- 以表格形式呈现
- 确保完全没有技术背景的人也能通过这张表建立基本认知

---

### 维度二：逐行/逐段详细解释

按照文件的自然顺序（代码行号或逻辑段落），逐行或逐段解释：
- 每一行（或每一个逻辑代码块）的具体功能是什么
- 它在整个文件中扮演什么角色
- 在实际开发中，这个部分对应什么应用场景

---

### 维度三：专有名词通俗化

对文件中出现的**所有**专业术语和技术名词：
- 在**首次出现时**就给出通俗解释，不要假设读者已经知道
- 必须使用生活中的类比（如"管家""快递""积木""超市"等日常事物）
- 同一个名词在不同上下文中含义不同时，要分别解释
- 示例风格：
  > **Artifact（制品）**：项目经过编译打包后最终生成的文件。类比：你做了一
  > 个蛋糕，蛋糕就是 artifact。面粉鸡蛋是依赖，烤箱是插件，做蛋糕的过程
  > 是构建。

---

### 维度四：可修改项举例与影响分析

对文件中每一个**可以修改**的配置项或代码段：
1. 给出具体的修改示例（修改前 vs 修改后的代码对比）
2. 详细说明修改后的影响，包括但不限于：
   - 界面/外观有什么变化（如果有的话，用示意图或文字描述）
   - 代码运行行为有什么变化
   - 依赖关系有什么变化
   - 性能有什么影响
3. 说明在实际产品开发中：
   - 是否需要修改？（✅需要 / ⚠️视情况 / ❌不需要）
   - 典型的修改场景是什么
   - 修改时需要注意什么

---

### 维度五：段落总结

在每一段/每一部分的解释末尾，添加一段通俗总结：
- 用大白话概括该部分的核心要点
- 说明该部分在整个文件中的地位（如"基础开头""核心逻辑""收尾工作"）
- 风格示例：
  > 这 5 行代码组成了整个文件的基础开头，就像一封信的"抬头"——告诉收件
  > 人这封信来自哪里、用什么语言书写。没有这几行，对方根本不知道该怎么
  > 读这封信。这是所有 Maven 项目的"标准模板"，永远不需要修改。

---

### 维度六：整体架构与关系图解

> （仅当解析对象为多文件或整个工程时输出此部分）

- 使用 Mermaid 语法绘制模块/文件之间的依赖关系图、调用关系图或层次结构图
- 对图中的每个节点和箭头给出通俗解释
- 说明各模块/文件是如何像积木一样拼装协作的
- 如果是工程项目，还需说明构建/启动顺序
- 用生活化类比总结整体架构（如"像一家公司的组织架构"）

---

## 输出格式要求

1. 使用清晰的标题层级（H2 用于大段落、H3 用于子段落、H4 用于细节）
2. 各大段落之间使用分隔线 `---` 分隔
3. 每个段落内部按此顺序组织：逐行解释 → 专有名词解释 → 可修改项分析 → 段落总结
4. 可修改项分析中使用代码块展示修改前后的对比
5. 在文档末尾提供一份"全文总览速查表"，用表格形式汇总所有关键信息
6. 涉及风险的操作，用 🔴（高风险）、🟡（中风险）、🟢（低风险）标注

## 语言风格要求

- 面向非计算机专业人员也能看懂的程度
- 每个概念首次出现时必须用生活化类比解释
- 避免"显然""很容易理解""不言而喻"等假设读者已知的表述
- 宁可多说一句，不要省略关键解释
```

### 使用说明

**场景一：解析单个文件**

```
# 代码/文档深度解析指令

## 解析对象
- 类型：单文件
- 路径：E:\WorkSpace\myproject\src\main\resources\application.yml
- 语言/格式：YAML
```


**场景二：解析多个文件**

```
## 解析对象
- 类型：多文件
- 路径：
  - src/main/java/com/example/controller/UserController.java
  - src/main/java/com/example/service/UserService.java
  - src/main/java/com/example/mapper/UserMapper.java
- 语言/格式：Java
```


**场景三：解析整个工程**

```
## 解析对象
- 类型：整个工程
- 路径：E:\WorkSpace\myproject
- 语言/格式：自动识别
```


**场景四：只关注某个文件的特定部分**

```
## 解析对象
- 类型：单文件
- 路径：src/main/java/com/example/config/SecurityConfig.java
- 语言/格式：Java
- 补充说明：重点解析权限配置相关代码，其他部分简要带过即可
```


---

将上面的模板内容保存为一份文本文件或笔记，以后使用时只需复制模板、填入路径即可。如果某次不需要某个维度（比如解析单个简单文件时不需要"维度六：架构图解"），在模板中加一行 `维度六不需要输出` 即可跳过。
