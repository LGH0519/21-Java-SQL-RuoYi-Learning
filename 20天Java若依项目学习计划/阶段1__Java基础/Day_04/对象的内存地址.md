这是一个**非常经典、也非常容易让人困惑的问题**，但结论其实很简单：

> **你在 Debug 里看到的“地址”，和 `System.out.println(obj)` 打印出来的“地址”，不是同一种东西。**

下面我一步一步解释清楚。

---

## 一、先说结论（重点）

|场景|你看到的“地址”是什么|
|---|---|
|`System.out.println(obj)`|`类名@hashCode`（`hashCode` 不一定是内存地址）|
|Debug 窗口|JVM / IDE 显示的**对象唯一标识**（通常是内部对象 ID）|
|真实内存地址|**你看不到**，Java 也不保证给你看|

👉 **所以两者当然不一样，它们本来就不是同一个东西。**

---

## 二、`System.out.println(obj)` 打印的是什么？

当你写：

```
Object obj = new Object();
System.out.println(obj);
```

输出类似：

```
java.lang.Object@1b6d3586
```

这个 `@` 后面的 `1b6d3586` 是什么？

### ✅ 是 `hashCode()` 的十六进制，不是内存地址

调用链是：

```
obj.toString()
→ getClass().getName() + "@" + Integer.toHexString(hashCode())
```

而 `Object.hashCode()` 的默认实现：

- **可能**用内存地址算
- **也可能**用随机数 / 线程状态 / 对象 ID
- **而且对象移动后，地址会变，但 hashCode 不变**

👉 所以：**`toString()` 里的“地址”只是个标识，不是真实内存地址**

---

## 三、Debug 里看到的又是什么？

在 IDEA / Eclipse 里 Debug 时，你会看到类似：

```
obj = Object@612
```

或者：

```
Object@1b6d3586
```

这个 `@612` 或 `@1b6d3586` 是：

### ✅ IDE / JVM 给对象分配的“显示 ID”

不同来源：

|来源|说明|
|---|---|
|IDEA Debug|对象唯一编号（方便你区分对象）|
|HotSpot JVM|内部对象标识|
|`hashCode()`|有时一致，有时不一致|

👉 **这是给调试用的，不是内存地址，也不等于 `toString()` 的结果**

---

## 四、为什么 JVM 不给你“真实内存地址”？

因为 Java 有 **垃圾回收（GC）**。

### 关键事实：

- 对象在堆里 **会被移动**
- GC 会把对象从 Eden → Survivor → Old
- 甚至做 **压缩（Compact）**

如果 `hashCode()` 或 `toString()` 依赖真实地址：

> 对象一移动，地址就变了，hashCode 也变
> 
> → `HashMap` / `HashSet` 直接崩

所以 JVM 的设计是：

> **hashCode 一旦生成，就固定不变**

即使对象在内存里搬了 10 次家，它的 `hashCode` 也不会变。

---

## 五、用一个例子彻底看清楚

```
class Demo {
    public static void main(String[] args) {
        Object a = new Object();
        Object b = new Object();

        System.out.println(a);
        System.out.println(b);
        System.out.println(a.hashCode());
        System.out.println(b.hashCode());
    }
}
```

输出可能是：

```
java.lang.Object@1b6d3586
java.lang.Object@4554617c
460141958
1163157884
```

Debug 里你看到的可能是：

```
a = Object@1
b = Object@2
```

### 为什么不一样？

|显示位置|来源|
|---|---|
|`println`|`hashCode()`|
|Debug|JVM 内部对象 ID|
|内存地址|不可见|

---

## 六、什么时候两者会“看起来一样”？

有时候你会看到：

```
Object@1b6d3586
```

Debug 里也是 `1b6d3586`，这是因为：

- IDE 默认用 `toString()` 显示对象
- 或者 `hashCode` 刚好被用作对象 ID

👉 **这是巧合，不是规则**

---

## 七、面试 / 实战一句话总结

> **Java 里你永远看不到对象的真实内存地址。**

- `toString()` 里的 `@xxx` 是 `hashCode`
- Debug 里的是对象 ID
- 两者来源不同，当然可能不一样
- 这是 JVM 为了 GC 和稳定性故意设计的

---

## 八、如果你只是想“区分是不是同一个对象”

用这个：

```
System.out.println(obj1 == obj2); // true = 同一个对象
```

或者：

```
System.out.println(System.identityHashCode(obj));
```

`identityHashCode` 是**最接近对象身份的东西**，但依然不是地址。
