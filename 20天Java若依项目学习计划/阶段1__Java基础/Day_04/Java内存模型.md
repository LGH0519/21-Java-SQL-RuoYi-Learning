## 一句话总览

JVM 运行时把内存分成几个区域，各管各的：

```
┌─────────────────────────────────────────────┐
│                  JVM 内存                      │
├──────────┬──────────┬──────────┬────────────┤
│  堆区     │ 方法区    │ 虚拟机栈  │ 本地方法栈  │
│  Heap     │ Method   │ Stack    │ Native     │
│           │ Area     │          │ Stack      │
├──────────┴──────────┴──────────┴────────────┤
│              程序计数器                       │
│           Program Counter Register           │
└─────────────────────────────────────────────┘
```

---

## 1️⃣ 堆区（Heap）—— 对象住的地方

**所有 `new` 出来的东西都在这里。**

```
Object obj = new Object(); // new 出来的对象在堆里
```

特点：

|特点|说明|
|---|---|
|所有线程共享|一个 JVM 只有一个堆|
|存什么|对象实例、数组|
|生命周期|GC 管，不用你 `free`|
|最大|通常是 JVM 内存里最大的一块|

堆内部还有细分（大概知道就行）：

```
堆
├── 新生代（Young）
│   ├── Eden（伊甸园）
│   ├── Survivor 0
│   └── Survivor 1
└── 老年代（Old）
```

新对象先放 Eden，经过几次 GC 还活着的，搬到老年代。

---

## 2️⃣ 方法区（Method Area）—— 类信息住的地方

**存"类长什么样"的信息。**

包括：

- 类的结构信息（类名、父类、接口）
- 方法代码（字节码）
- 静态变量（`static` 字段）
- 常量池（字符串常量等）

```
class User {
    static int count = 0;  // count 在方法区
}
```

|特点|说明|
|---|---|
|所有线程共享|一个 JVM 只有一个方法区|
|存什么|类信息、static 变量、常量|
|生命周期|和 JVM 一样长|
|别名|JDK 8 之前叫"永久代"（PermGen），JDK 8+ 叫"元空间"（Metaspace）|

⚠️ **JDK 8 的变化**：元空间不在 JVM 内存里了，用的是本地内存（Native Memory），所以不容易再出现 `PermGen OutOfMemoryError`。

---

## 3️⃣ 虚拟机栈（VM Stack）—— 方法执行的地方

**每个线程一个栈，每个方法调用 = 一个栈帧压栈。**

```
void a() {
    int x = 1;
    b();
}

void b() {
    int y = 2;
}
```

调用 `a()` 时：

```
栈（线程1）
├── b() 栈帧        ← 当前执行
│   ├── 局部变量 y = 2
│   └── 操作数栈
├── a() 栈帧
│   ├── 局部变量 x = 1
│   └── 操作数栈
└── main() 栈帧
```

每个栈帧里有：

|组成部分|干嘛的|
|---|---|
|局部变量表|存方法参数、局部变量|
|操作数栈|字节码执行时临时放数据|
|方法返回地址|方法执行完回到哪|
|动态链接|指向方法区里的类信息|
|特点|说明|
|---|---|
|线程私有|每个线程各自一份，不共享|
|存什么|局部变量（基本类型）、对象引用|
|生命周期|方法调用结束，栈帧出栈，自动释放|
|异常|栈深度超过限制 → `StackOverflowError`|

---

## 4️⃣ 本地方法栈（Native Method Stack）

**跟虚拟机栈差不多，但是给 native 方法用的。**

```
// 用 native 关键字声明，实现在 C/C++ 里
public native void sleep(long millis);
```

|特点|说明|
|---|---|
|线程私有|跟虚拟机栈一样|
|存什么|native 方法的调用状态|
|区别|虚拟机栈管 Java 方法，本地方法栈管 native 方法|

实际上 HotSpot JVM 把这两个栈合在一起了，但你概念上要分开理解。

---

## 5️⃣ 程序计数器（Program Counter Register）

**记录当前线程执行到哪条指令了。**

|特点|说明|
|---|---|
|线程私有|每个线程一个|
|存什么|当前执行的字节码指令地址|
|唯一不会 OOM 的区域|很小，固定大小|

如果线程在执行 native 方法，计数器值为 `undefined`。

---

## 6️⃣ 一张表总结

|区域|线程共享？|存什么|生命周期|
|---|---|---|---|
|**堆**​|✅ 共享|对象实例、数组|GC 管|
|**方法区**​|✅ 共享|类信息、static、常量|JVM 级别|
|**虚拟机栈**​|❌ 私有|局部变量、方法调用|方法结束释放|
|**本地方法栈**​|❌ 私有|native 方法调用|方法结束释放|
|**程序计数器**​|❌ 私有|指令地址|线程结束释放|

## 7️⃣ 用一个完整例子串起来

```
public class Demo {
    static int count = 0;          // → 方法区

    public static void main(String[] args) {  // main 栈帧 → 虚拟机栈
        int local = 10;            // → 虚拟机栈（局部变量表）
        User u = new User("张三"); // u 引用 → 虚拟机栈
                                  // User 对象 → 堆
        u.sayHi();                 // sayHi 栈帧压栈 → 虚拟机栈
    }
}

class User {
    String name;                   // → 堆（作为对象的一部分）

    User(String name) {
        this.name = name;
    }

    void sayHi() {
        System.out.println(name);  // 方法字节码 → 方法区
    }
}
```

内存分布：

```
方法区：Demo 类信息、User 类信息、count = 0
堆：    User 对象（name = "张三"，字符串在常量池）
栈：    main 帧(local=10, u=引用) → sayHi 帧
```

## 8️⃣ 为什么了解这些有用？

|场景|用到的知识|
|---|---|
|为什么局部变量线程安全？|栈是线程私有的|
|为什么 static 变量全局共享？|static 在方法区，所有线程共享|
|为什么 new 的对象到处传？|引用在栈上，对象在堆上|
|`StackOverflowError` 怎么来的？|栈帧太多（递归没出口）|
|`OutOfMemoryError` 怎么来的？|堆/方法区撑爆了|
|前面说的 `transient` 序列化|对象在堆里，序列化是把堆对象变成字节|

## 一句话结论

|JDK 版本|String 常量池在哪|
|---|---|
|**JDK 6 及之前**​|方法区（永久代 PermGen）|
|**JDK 7**​|堆（Heap）|
|**JDK 8+**​|堆（Heap）|

> **现在你用的如果是 JDK 8+，String 常量池就在堆里。**

---

## 为什么 JDK 7 要搬家？

### JDK 6 的布局

```
JVM 内存
├── 堆
│   └── 普通对象
├── 方法区（PermGen 永久代）
│   ├── 类信息
│   ├── static 变量
│   └── String 常量池  ← 在这
```

**坑在哪？**

- 永久代有固定大小，不能自动扩容
- 大量字符串（比如从文件/网络读取的）不断 `intern()` 进常量池
- 直接撑爆 → `java.lang.OutOfMemoryError: PermGen space`

这是个**真实的生产事故**，很多老项目都踩过。

---

### JDK 7 的改动

```
JVM 内存
├── 堆
│   ├── 普通对象
│   └── String 常量池  ← 搬到这里了
├── 方法区（PermGen，但常量池已迁出）
│   ├── 类信息
│   └── static 变量
```

好处：

- 堆可以自动扩容
- GC 可以回收常量池里的字符串
- 不再容易 OOM

---

### JDK 8 的布局

```
JVM 内存
├── 堆
│   ├── 普通对象
│   └── String 常量池  ← 在这
├── 元空间（Metaspace，本地内存）
│   ├── 类信息
│   └── static 变量
```

永久代被彻底干掉了，换成元空间（用的是操作系统本地内存），但 **String 常量池留在堆里**没变。

## 那 `String s = "abc"` 到底发生了什么？

```
String s1 = "abc";
String s2 = "abc";
String s3 = new String("abc");
```

内存里：

```
堆
├── String 常量池
│   └── "abc"（只有一个）
├── String 对象（s3 指向的）
│   └── value[] 指向常量池里的 "abc"
```

引用关系：

```
s1 ──→ 常量池里的 "abc"
s2 ──→ 常量池里的 "abc"   （同一个）
s3 ──→ 堆里 new 出来的 String 对象 → 常量池里的 "abc"
```

所以：

```
s1 == s2;      // true，同一个常量池对象
s1 == s3;      // false，s3 是堆里新对象
s1.equals(s3); // true，内容一样
```

---

## `intern()` 又是什么？

```
String s = new String("abc").intern();
```

`intern()` 的逻辑：

1. 看常量池里有没有 `"abc"`
2. 有 → 返回常量池里的引用
3. 没有 → 把字符串放入常量池，返回引用

所以：

```
String s1 = "abc";
String s2 = new String("abc").intern();
s1 == s2; // true
```

## 一个经典面试题（坑中之坑）

```
String s1 = new String("abc");
```

**这行代码创建了几个对象？**

答案：**1 个或 2 个**

- 如果常量池里**没有**​ `"abc"`：
    - 常量池创建一个 `"abc"`（1 个）
    - 堆里 `new` 一个 String 对象（1 个）
    - 共 **2 个**
- 如果常量池里**已经有**​ `"abc"`：
    - 只在堆里 `new` 一个 String 对象
    - 共 **1 个**

---

## 为什么这很重要？

|场景|影响|
|---|---|
|大量字符串拼接|产生大量临时对象，GC 压力|
|用 `intern()` 去重|省内存，但 JDK 6 可能 OOM|
|用 `==` 比较字符串|可能得到 false（不同对象）|
|理解 `String` 不可变|常量池复用是安全的|
