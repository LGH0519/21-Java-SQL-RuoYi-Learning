# 逐一解答你的 4 个问题

## 问题 1：方法不能嵌套，对吧？

**对，Java 中方法不能嵌套定义。** 你不能在一个方法里面再定义一个方法。

```java
public class User {
    public void outer() {
        // ❌ 编译报错！Java 不允许在方法里定义方法
        public void inner() {
            System.out.println("不行");
        }
    }
}
```

### 但可以用"替代方案"实现类似效果

| 替代方案 | 写法 | 说明 |
|---------|------|------|
| **局部内部类** | 在方法里定义一个类，类里写方法 | 曲线救国 |
| **Lambda 表达式** | `() -> { ... }` | 本质是匿名内部类的简化写法 |
| **私有方法** | 在类里定义 `private` 方法 | 最常用的方式 |

```java
public class User {
    public void outer() {
        // ✅ 方案1：Lambda（本质是匿名内部类）
        Runnable r = () -> {
            System.out.println("我在方法里面，但我是 Lambda");
        };
        r.run();

        // ✅ 方案2：局部内部类
        class Inner {
            void hello() {
                System.out.println("我是局部内部类的方法");
            }
        }
        new Inner().hello();
    }

    // ✅ 方案3：私有方法（最常用）
    private void helper() {
        System.out.println("我是辅助方法");
    }
}
```

> 类比：方法不能嵌套就像"俄罗斯套娃只能套盒子，不能套盒子"——但你可以把小盒子放在大盒子旁边（私有方法），或者在盒子里放一个能打开的小机关（Lambda）。

## 问题 2：匿名内部类的适用场景

### 你的感觉是对的！

匿名内部类确实很像"类实例化之后加一个代码块"：

```java
// 普通实例化
Runnable r = new MyRunnable();

// 匿名内部类 = 实例化 + 立刻重写方法
Runnable r = new Runnable() {    // ← 像实例化
    @Override                     // ← 像加了个代码块
    public void run() {
        System.out.println("跑了！");
    }
};
```

### 适用场景：只需要用一次的对象

| 场景 | 说明 | 例子 |
|------|------|------|
| **事件监听** | 按钮点击、数据变化时执行一段逻辑 | Swing 的按钮点击事件 |
| **线程创建** | 快速创建一个线程任务 | `new Thread(() -> {...}).start()` |
| **接口实现** | 只需要实现一次接口，不值得单独写一个类 | 排序比较器 `Comparator` |
| **回调函数** | 异步操作完成后执行某段代码 | 网络请求的回调 |

### 对比：什么时候用匿名内部类，什么时候单独写类？

```java
// ❌ 不值得：只用一次，却单独写了一个类
class MyComparator implements Comparator<String> {
    @Override
    public int compare(String a, String b) {
        return a.length() - b.length();
    }
}
list.sort(new MyComparator());  // 这个类只在这里用了一次

// ✅ 推荐：匿名内部类（或 Lambda）
list.sort(new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return a.length() - b.length();
    }
});

// ✅ 更推荐：Lambda（Java 8+）
list.sort((a, b) -> a.length() - b.length());
```

| 判断标准 | 用匿名内部类/Lambda | 单独写类 |
|---------|-------------------|---------|
| 使用次数 | 只用 1 次 | 多处复用 |
| 逻辑复杂度 | 简单（几行代码） | 复杂（几十行以上） |
| 是否需要状态 | 不需要额外字段 | 需要成员变量 |

> 类比：匿名内部类就像**一次性筷子**——吃一顿饭就扔了，不值得洗。单独写类就像**家里的筷子**——反复使用，值得好好保养。

## 问题 3：类嵌套和接口嵌套怎么调用？为什么？

### 类嵌套的调用方式

```java
public class Outer {
    // ① 普通内部类（非 static）
    class Inner {
        void hello() { System.out.println("Hello"); }
    }

    //  静态内部类
    static class StaticInner {
        void hello() { System.out.println("Static Hello"); }
    }
}
```

| 类型 | 调用方式 | 为什么这样？ |
|------|---------|-------------|
| 普通内部类 | `new Outer().new Inner()` | 它依赖外部类的实例，必须先有"爸爸"才能有"儿子" |
| 静态内部类 | `new Outer.StaticInner()` | 它是独立的，不需要外部类实例，直接用"公司名.部门名"访问 |

```java
// 普通内部类：必须先创建外部类对象
Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();  // 通过外部对象创建
inner.hello();

// 静态内部类：直接创建
Outer.StaticInner staticInner = new Outer.StaticInner();  // 不需要外部对象
staticInner.hello();
```

> 类比：
> - 普通内部类 = **亲儿子**——必须爸爸在才能存在（`爸爸.儿子`）
> - 静态内部类 = **独立分公司**——和总公司有关系，但可以独立运营（`总公司.分公司`）

---

### 接口嵌套的调用方式

```java
public interface Map<K, V> {
    V put(K key, V value);

    interface Entry<K, V> {    // 嵌套的子接口
        K getKey();
        V getValue();
    }
}
```

| 调用方式 | 说明 |
|---------|------|
| `Map.Entry<String, Integer>` | 用"外层接口.内层接口"的方式引用 |

```java
// 使用嵌套接口作为类型
Map.Entry<String, Integer> entry = ...;

// 实现嵌套接口
class MyEntry implements Map.Entry<String, Integer> {
    private String key;
    private Integer value;

    @Override
    public String getKey() { return key; }

    @Override
    public Integer getValue() { return value; }

    @Override
    public Integer setValue(Integer value) {
        this.value = value;
        return value;
    }
}
```

**为什么用 `.` 而不是 `new`？**

因为接口不能实例化（不能 `new`），嵌套接口只是一个**类型定义**，不是对象。你用 `Map.Entry` 是在说"我要用 Map 里面的 Entry 这个类型"，就像说"我要用苹果公司.iOS 系统"一样——是在引用，不是在创建。

---

### 总结对比

| 嵌套类型 | 调用/使用方式 | 原因 |
|---------|-------------|------|
| 普通内部类 | `outer.new Inner()` | 依赖外部实例，必须先有外部对象 |
| 静态内部类 | `new Outer.StaticInner()` | 独立存在，直接通过类名访问 |
| 嵌套接口 | `Map.Entry<K, V>`（作为类型） | 接口不能 new，只能作为类型引用 |

## 问题 4：Map.Entry 相关知识点及传参

### 4.1 Map.Entry 是什么？

`Map.Entry` 是 `Map` 接口里嵌套的一个**子接口**，代表 Map 中的**一对键值对**（一个 Entry = 一个 key + 一个 value）。

```
Map（整个地图）
  ├── Entry1: "张三" → 25
  ├── Entry2: "李四" → 30
  └── Entry3: "王五" → 28
```

> 类比：Map 是一本**通讯录**，每个 Entry 就是通讯录里的**一行记录**——左边是名字（key），右边是电话（value）。

---

### 4.2 Entry 接口的方法

```java
interface Entry<K, V> {
    K getKey();          // 获取键
    V getValue();        // 获取值
    V setValue(V value); // 修改值，返回旧值

    // Java 8+ 新增的静态方法
    static <K extends Comparable<? super K>, V> Comparator<Map.Entry<K, V>> comparingByKey() { ... }
    static <K, V extends Comparable<? super V>> Comparator<Map.Entry<K, V>> comparingByValue() { ... }
}
```

| 方法 | 作用 | 示例 |
|------|------|------|
| `getKey()` | 拿到 key | `"张三" → 25` 中拿到 `"张三"` |
| `getValue()` | 拿到 value | `"张三" → 25` 中拿到 `25` |
| `setValue(V)` | 修改 value | 把 `25` 改成 `26` |
| `comparingByKey()` | 按 key 排序的比较器 | 按名字字母顺序排 |
| `comparingByValue()` | 按 value 排序的比较器 | 按年龄大小排 |

---

### 4.3 怎么遍历 Map 中的 Entry？

这是开发中最常见的用法：

```java
Map<String, Integer> map = new HashMap<>();
map.put("张三", 25);
map.put("李四", 30);
map.put("王五", 28);

// 方式1：entrySet() 遍历（最常用，推荐）
for (Map.Entry<String, Integer> entry : map.entrySet()) {
    System.out.println(entry.getKey() + " → " + entry.getValue());
}
// 输出：
// 张三 → 25
// 李四 → 30
// 王五 → 28

// 方式2：Lambda 写法（更简洁）
map.forEach((key, value) -> {
    System.out.println(key + " → " + value);
});

// 方式3：只遍历 key
for (String key : map.keySet()) {
    System.out.println(key);
}

// 方式4：只遍历 value
for (Integer value : map.values()) {
    System.out.println(value);
}
```

---

### 4.4 Entry 的传参（泛型）

`Map.Entry<K, V>` 有**两个泛型参数**：

| 泛型参数 | 含义 | 例子 |
|---------|------|------|
| `K` | Key 的类型 | `String`、`Integer`、`Long` |
| `V` | Value 的类型 | `Integer`、`User`、`List<String>` |

```java
// K=String, V=Integer
Map.Entry<String, Integer> entry1;

// K=Long, V=User
Map.Entry<Long, User> entry2;

// K=String, V=List<String>（value 是列表）
Map.Entry<String, List<String>> entry3;
```

> 类比：`K` 和 `V` 就像表格的"列头"——K 列写什么类型、V 列写什么类型，你说了算。一旦定好，这个 Map 里所有的 Entry 都必须遵守。

---

### 4.5 若依项目中 Map.Entry 的典型用法

```java
// 场景：统计每个用户的操作次数
Map<String, Integer> userCountMap = new HashMap<>();
userCountMap.put("admin", 100);
userCountMap.put("editor", 50);

// 按操作次数排序（从大到小）
List<Map.Entry<String, Integer>> sorted = new ArrayList<>(userCountMap.entrySet());
sorted.sort(Map.Entry.comparingByValue(Comparator.reverseOrder()));

for (Map.Entry<String, Integer> entry : sorted) {
    System.out.println(entry.getKey() + ": " + entry.getValue() + " 次");
}
// 输出：
// admin: 100 次
// editor: 50 次
```
