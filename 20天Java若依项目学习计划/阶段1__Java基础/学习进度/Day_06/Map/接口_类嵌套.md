## 可以！接口和类都可以嵌套定义

---

## 一、接口嵌套定义

**可以。** 接口里面可以定义：
- 子接口
- 内部类
- 常量
- 方法

### 实际例子：`Map` 接口里就嵌套了 `Entry` 接口

```java
public interface Map<K, V> {

    // Map 接口自身的方法
    V put(K key, V value);
    V get(Object key);
    int size();

    //  嵌套的子接口
    interface Entry<K, V> {
        K getKey();
        V getValue();
        V setValue(V value);
    }
}
```

**使用方式：**

```java
Map<String, Integer> map = new HashMap<>();
map.put("张三", 25);

// 通过 Map.Entry 访问嵌套接口
Map.Entry<String, Integer> entry = map.entrySet().iterator().next();
System.out.println(entry.getKey());    // "张三"
System.out.println(entry.getValue());  // 25
```

> 类比：就像"公司"（`Map`）里面有一个"员工档案部门"（`Entry`）——你要找员工信息，得通过"公司.员工档案部门"来访问。

## 二、类嵌套定义

**也可以。** 类里面可以定义：
- 内部类（普通内部类）
- 静态内部类
- 局部内部类（方法里面定义类）
- 匿名内部类

### 4 种嵌套类的对比

| 类型 | 写法 | 特点 | 类比 |
|------|------|------|------|
| **普通内部类** | 类里面直接定义类 | 能访问外部类的所有成员（包括 private） | 儿子住在爸爸家里，能用爸爸的所有东西 |
| **静态内部类** | `static` 修饰的内部类 | 不能访问外部类的实例成员，只能访问静态成员 | 独立的分公司——和总公司有关系，但财务独立 |
| **局部内部类** | 方法里面定义类 | 只在方法内有效，出了方法就没了 | 临时工——只在某个项目中存在 |
| **匿名内部类** | 不写类名，直接 new 接口/类 | 一次性使用，没有名字 | 一次性手套——用完就扔 |

### 代码示例

```java
public class Outer {
    private String name = "外部类";

    // ① 普通内部类
    class Inner {
        void show() {
            System.out.println(name);  // ✅ 能访问外部类的 private 成员
        }
    }

    //  静态内部类
    static class StaticInner {
        void show() {
            // System.out.println(name);  ❌ 不能访问外部类的实例成员
        }
    }

    // ③ 局部内部类（在方法里定义）
    void doSomething() {
        class LocalInner {
            void hello() {
                System.out.println("我是局部内部类");
            }
        }
        new LocalInner().hello();
    }

    // ④ 匿名内部类
    void doAnother() {
        Runnable r = new Runnable() {
            @Override
            public void run() {
                System.out.println("我是匿名内部类");
            }
        };
        r.run();
    }
}
```

## 三、嵌套的层级限制

**理论上可以无限嵌套**，但实际开发中**最多嵌套 2 层**，再深就难以维护了。

```java
// ✅ 常见：1 层嵌套
public class A {
    class B { }           // A.B
}

// ✅ 可以接受：2 层嵌套
public class A {
    class B {
        class C { }       // A.B.C
    }
}

// ❌ 不推荐：3 层以上
public class A {
    class B {
        class C {
            class D { }   // A.B.C.D —— 太深了，没人看得懂
        }
    }
}
```

## 四、接口和类嵌套的对比

| 对比项 | 接口嵌套 | 类嵌套 |
|--------|---------|--------|
| 能否嵌套？ | ✅ 能 | ✅ 能 |
| 嵌套的内容 | 子接口、常量、方法 | 内部类、方法、字段 |
| 嵌套成员的默认修饰符 | `public static`（自动的） | 取决于是否加 `static` |
| 常见场景 | `Map.Entry`、`List.Iterator` | 内部类、Builder 模式、匿名类 |
| 访问方式 | `Map.Entry` | `Outer.Inner` 或 `new Outer().new Inner()` |

## 五、若依项目中的实际例子

```java
// HashMap 中的 Entry（静态内部类）—— 来自 JDK 源码
static class Node<K,V> implements Map.Entry<K,V> {
    final int hash;
    final K key;
    V value;
    Node<K,V> next;
}
```

这里 `Node` 是 `HashMap` 的**静态内部类**，同时它实现了 `Map.Entry` 这个**嵌套接口**。一个类同时用到了两种嵌套机制。

---

## 一句话总结

> **接口和类都可以嵌套定义。** 接口里嵌套子接口（如 `Map.Entry`），类里嵌套内部类（4 种形式）。嵌套的本质就是"大盒子里装小盒子"——外层是大的分类，内层是更细的分类。实际开发中嵌套不超过 2 层，否则代码会变得难以阅读。
