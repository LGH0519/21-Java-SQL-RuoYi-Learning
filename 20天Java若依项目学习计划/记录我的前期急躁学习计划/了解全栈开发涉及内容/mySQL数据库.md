# MySQL 常用命令与系统库详解

> [!NOTE] 核心概念
> MySQL 是一个 C/S（客户端/服务器）架构的软件。`net` 命令操作的是**服务进程**，而 `mysql` 命令操作的是**数据库实例**。

## 🛠️ 一、基础服务与连接命令

### 命令结构图解
`mysql -u root -p`
  │      │   │
  │      │   └── 需要密码登录
  │      └────── 用户名是 root
  └───────────── 使用 MySQL 客户端工具

### 常用运维命令
- `net start MySQL` → 启动 MySQL 服务
- `net stop MySQL` → 关闭 MySQL 服务
- `mysql -u root -p` → 进入 MySQL 交互命令行
- `exit;` → 退出 MySQL 交互命令行

## 📖 二、权限配置命令拆解

当你需要开启远程连接（例如用 DBeaver 连接）时，需要执行以下 SQL：

| 命令 | 含义 | 为什么需要？ |
| :--- | :--- | :--- |
| `USE mysql;` | 切换到名为 `mysql` 的系统数据库 | 该库存储了用户权限信息（`user` 表），是 MySQL 的“安保中心”。 |
| `UPDATE user SET Host = '%' WHERE User = 'root' AND Host = 'localhost';` | 将 `root` 用户的登录限制从本机改为任意主机（`%`） | 允许局域网或云服务器上的工具远程连接 MySQL。 |
| `FLUSH PRIVILEGES;` | 重新加载权限表 | 修改权限后必须执行此命令，否则修改不会立即生效。 |
| `exit;` | 退出命令行 | 结束会话。 |

## 🏢 三、形象化类比：大楼与房间

> [!EXAMPLE] 理解 MySQL 的逻辑结构
> 用“大楼”来类比 MySQL 的架构，有助于理解层级关系：

| 概念 | 类比 | 说明 |
| :--- | :--- | :--- |
| **MySQL 服务** | 🏢 **一栋大楼** | 电脑上运行的 MySQL 进程实例。 |
| **数据库 (Database)** | 🏠 **大楼里的房间** | 每个项目独立的数据空间，如 `ry-vue`（若依）、`library`（图书系统）。 |
| **`USE mysql;`** | 🔑 **进入“安保部”房间** | `mysql` 库是特殊的系统库，专门存放用户权限表。 |

## ✅ 四、关于分号 `;` 的使用规范

**在 MySQL 交互式命令行中，分号 `;` 是语句结束符，必须添加。**

| 场景 | 是否要加 `;` | 说明 |
| :--- | :--- | :--- |
| **交互式命令行** (`mysql>`) | ✅ **必须加** | 不加 `;` 按回车，系统会认为语句未结束，出现 `->` 等待输入。 |
| **SQL 脚本文件** (.sql) | ✅ 建议加 | 用于分隔多条语句，确保批量执行无误。 |
| **编程语言调用** (Java/Python) | ❌ 通常不加 | 代码中通过 API 执行单条 SQL，驱动会自动处理。 |

## 📂 五、MySQL 四大系统数据库详解

MySQL 安装后默认包含四个系统库，了解它们有助于排查权限和性能问题。

### 1. `information_schema`（信息模式）
- **定位**：MySQL 的**“数据字典”**或**“全景地图”**。
- **内容**：存储所有数据库名、表结构、字段类型、索引信息等元数据。
- **用途**：当你用 IDEA 或 DBeaver 查看表结构时，就是在查询这个库。
- **权限**：❌ 只读，不可修改。

### 2. `mysql`（核心权限库）
- **定位**：MySQL 的**“安保人事部”**。
- **内容**：存储用户账号 (`user` 表)、密码、访问主机限制 (`Host`)、权限信息。
- **用途**：刚才执行的 `UPDATE user ...` 就在操作这个库。
- **权限**：✅ 可修改，但需谨慎。

### 3. `performance_schema`（性能监控）
- **定位**：MySQL 的**“监控室”**。
- **内容**：实时记录服务器运行指标，如锁等待、I/O 消耗、连接状态等。
- **用途**：项目上线后性能调优、排查慢查询时使用。
- **权限**：❌ 只读。

### 4. `sys`（诊断视图）
- **定位**：MySQL 的**“体检报告”**。
- **内容**：基于 `performance_schema` 的汇总视图，数据更直观（如最慢的 SQL 列表）。
- **用途**：DBA 快速定位性能瓶颈。
- **权限**：❌ 只读。

> [!WARNING] 新手注意
> 日常开发中，99% 的时间你只需要关注自己创建的**业务数据库**（如 `ry-vue`）。**不要随意删除或修改这四个系统库**，否则可能导致 MySQL 无法启动或无法登录。
