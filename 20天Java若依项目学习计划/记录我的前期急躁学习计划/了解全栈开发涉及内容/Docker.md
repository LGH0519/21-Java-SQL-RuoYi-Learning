# Docker 核心概念与开发环境方案对比

> [!NOTE] 核心定义
> **Docker = 轻量级的“虚拟机”**。它把应用和它需要的所有环境（JDK、MySQL、Redis、Node.js 等）打包成一个**独立的容器**，在任何电脑上都能一键运行，彻底解决“在我电脑上能跑”的环境一致性问题。

## 🛠️ 一、环境搭建操作对比

| 你的操作 | Windows 本地开发（传统方式） | Docker 容器化（推荐方式） |
| :--- | :--- | :--- |
| **获取 Node.js** | 下载 `.msi` 安装包，双击安装 | 直接拉取 `node:18` 镜像 |
| **获取 JDK** | 下载 `.exe` 安装包，双击安装 | 直接拉取 `openjdk:11` 镜像 |
| **获取 MySQL** | 下载 `.msi` 安装包，配置服务 | 直接拉取 `mysql:8.0` 镜像 |
| **核心逻辑** | **“下载 → 安装 → 配置 → 运行”** | **“拉取 → 直接运行”** |

## 📊 二、方案深度对比分析

| 对比维度 | **Windows 直接安装**<br>*(你现在的方案)* | **Docker 方案**<br>*(容器化方案)* |
| :--- | :--- | :--- |
| **安装方式** | 分别下载 `.exe` 文件，手动双击安装，步骤繁琐。 | 在 Docker Desktop 中，用一条命令（如 `docker run`）拉取并运行官方镜像。 |
| **环境隔离** | 所有软件都直接装在 Windows 系统中，容易产生 DLL 冲突或端口占用。 | 每个软件（MySQL、Redis）都运行在独立的“容器”里，与宿主机及彼此完全隔离。 |
| **启动方式** | 作为 Windows 后台服务运行（需手动 `net start ...`）。 | 通过 `docker start/stop` 命令或 Docker Desktop 界面一键控制容器生命周期。 |
| **存储方式** | 程序放在 `C:\devTool`，数据放在 `C:\mysql-data` 等物理路径。 | 程序和数据默认在 Docker 虚拟硬盘里，可通过**“数据卷（Volume）”**指定存储位置。 |
| **数据持久化** | 直接读写硬盘上的物理文件，直观可见。 | **必须**通过“挂载卷（Bind Mount）”将容器内目录映射到 Windows 路径，否则容器删除后数据丢失。 |

---

> [!TIP] 针对若依项目的建议
> 对于若依（RuoYi）这类需要同时运行 **MySQL + Redis + 后端（Java） + 前端（Node）** 的项目，强烈建议使用 **Docker Compose**。
> 只需编写一个 `docker-compose.yml` 文件，一条命令 `docker-compose up -d` 即可启动全套环境，非常适合新手快速搭建标准化的开发环境。
