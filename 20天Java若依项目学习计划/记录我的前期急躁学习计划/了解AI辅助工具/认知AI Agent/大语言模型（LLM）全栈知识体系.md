# 🧠 大语言模型（LLM）全栈知识体系：新手小白入门指南

> [!TIP] 阅读指南
> 
> 本文档旨在梳理基于大语言模型（LLM）应用开发的核心概念。我们将从最基础的“文本接龙机器”开始，逐步扩展到参数调节、提示词工程、AI 智能体（Agent）以及企业级应用架构。

---

## 🌱 一、基础核心：LLM 到底是什么？

|名词|一句话概括（新手版）|
|---|---|
|**LLM (大语言模型)**​|一个超级强大的**“文本接龙机器”**，根据你前面说的话，预测下一个最可能的词（Token）并拼凑成回答。|
|**Transformer**​|现代 LLM 的底层骨架，核心能力是**“自注意力机制”**（读一段话时，能自动判断每个词和上下文中哪些词关联最强）。|
|**Token (词元)**​|模型的最小处理单位（中文约等于1个字或词，英文约等于词根），模型通过 Token 来理解语义。|
|**预训练 (Pre-training)**​|让模型“狂读整个互联网”，学会语法、常识和逻辑，是个“填词填空题”的过程。|
|**微调/对齐 (SFT & RLHF)**​|预训练后，用人工标注的高质量问答教它“怎么好好说话”，并用人类打分让它拒绝有害请求。|
|**上下文窗口 (Context Window)**​|大模型的“短期记忆容量”，限制了它一次能处理和理解的文字长度（如 4k, 128k tokens）。|
|**幻觉 (Hallucination)**​|模型“一本正经地瞎编”不知道的事实，这是目前所有大模型的通病，需要人工核查。|

## 🎛️ 二、参数详解：如何控制大模型的“脑洞”？

> [!NOTE] 一句话速记
> 
> **Temperature**​ 管“脑洞大小”，**Top-p**​ 管“用词范围”，**Top-k**​ 管“候选名单长度”。

|参数|核心含义|调节效果|推荐场景|
|---|---|---|---|
|**Temperature**  <br>_(温度)_|控制概率分布的平滑度。  <br>值越低，高分词优势越大；值越高，低分词机会越多。|📉 **调低 (0~0.3)**：输出更**确定**、保守、聚焦。  <br>📈 **调高 (0.7~1.0)**：输出更**随机**、有创意、发散。|调低：写代码、数学计算、事实问答。  <br>调高：写小说、诗歌、头脑风暴。|
|**Top-k**  <br>_(采样)_|每次只从概率最高的 **k**​ 个词中进行采样。|k 越小，输出越死板；k 越大，多样性越丰富（通常设 40~50）。|简单限制候选集，较少单独使用。|
|**Top-p**  <br>_(核采样)_|设置**累积概率阈值**。  <br>只保留概率加起来达到 p 的最小词汇集。|📉 **调低 (0.1~0.5)**：候选词更精准，减少胡言乱语。  <br>📈 **调高 (0.9~1.0)**：候选词更丰富，允许多样化表达。|最常用的多样性控制参数，与 Temperature 搭配。|
![[Pasted image 20260823174219.png]]

> [!WARNING] 最佳实践
> 1. **避免同时大幅调整**：通常建议 **Temperature** 和 **Top-p** 二选一进行微调。如果同时调高，可能>导致输出混乱；同时调低，可能导致输出过于死板。
>2. **代码与逻辑**：建议 `temperature: 0 ~ 0.3`，`top_p: 0.1 ~ 0.5`。
>3. **创意写作**：建议 `temperature: 0.7 ~ 1.0`，`top_p: 0.9 ~ 1.0`。
>4. **Greedy Decoding**：当 `temperature = 0` 且 `top_p = 1` 时，模型通常选择概率最高的词（贪>婪解码），结果最稳定。
 


## 💬 三、提示词工程 (Prompt Engineering)

| 名词                        | 一句话概括                                         |
| ------------------------- | --------------------------------------------- |
| **Prompt (提示词)**​         | 你给大模型的“指令”或“魔法咒语”，问得越具体，答案越到位。                |
| **Few-shot / Zero-shot**​ | 给模型举几个例子让它照做（Few-shot），或不给例子直接让它做（Zero-shot）。 |
| **CoT (思维链)**​            | 引导模型“一步步思考”，把复杂的推理过程写出来，从而提高准确率。              |
| **System Prompt**​        | 系统指令（如：“你是一名10年经验的Java架构师”），用于设定 AI 的角色和语气。   |

## 🏗️ 四、架构演进：LLM vs Workflow vs Agent

> [!EXAMPLE] 核心区别类比
> 
> - **LLM**：你问一句，它答一句（超级大脑，但被动）。
> - **Workflow (工作流)**：你规定了死步骤（如：输入 -> 调 LLM 摘要点 -> 发邮件），它按部就班执行，没有自主权。
> - **Agent (智能体)**：你给个目标，它自己拆解步骤、调工具、复盘修正，直到完成任务（有自主权的数字员工）。

### 1. AI Agent (智能体) 的构成

Agent = LLM (大脑) + 记忆 (Memory) + 规划 (Planning) + 工具 (Tools) + 循环 (Loop)。

|组件|一句话概括|
|---|---|
|**LLM (大脑)**​|负责理解意图、推理、做决策、生成计划。|
|**记忆 (Memory)**​|短期记忆（当前对话） + 长期记忆（向量数据库存储的外部知识）。|
|**规划 (Planning)**​|把大目标拆解成小步骤（如 ReAct, CoT），并处理异常。|
|**工具调用 (Tool Use)**​|Agent 的“手脚”，调用搜索引擎、API、数据库、代码解释器等。|
|**反思 (Reflection)**​|任务执行后的复盘能力，判断结果对错并优化方案。|

### 2. Agent Loop (智能体循环)

Agent 的核心运行逻辑是 **ReAct 循环**（推理+行动）：

1. **Think (思考)**：LLM 分析当前状态，决定下一步做什么。
2. **Act (行动)**：调用外部工具（如查数据库、联网搜索）。
3. **Observe (观察)**：获取工具返回的结果。
4. **Reflect (反思/检查)**：判断是否完成目标，没完成就回到“思考”步骤，形成闭环。

## 🚀 五、进阶应用：定制与增强

| 名词                    | 一句话概括                                          |
| --------------------- | ---------------------------------------------- |
| **RAG (检索增强生成)**​     | 给大模型配个“开卷考的百科全书”（外部知识库），让它先查资料再回答，解决知识过时和幻觉问题。 |
| **向量数据库**​            | 专门存储文本向量（语义身份证）的数据库，RAG 靠它快速找回相关知识。            |
| **Fine-tuning (微调)**​ | 用特定领域的数据（如你的公司文档）重新训练模型，让模型“内化”这些新知识，变成领域专家。   |
| **Embedding (词嵌入)**​  | 把文字转换成高维向量的技术，语义相近的词，向量距离也近。                   |

> [!TIP] RAG vs 微调 怎么选？
> 
> - 知识更新快、需要溯源 ➡️ **优先 RAG**（成本低，见效快）。
> - 模型行为/语气不对、需要固化风格 ➡️ **考虑微调**。
> - 工业界最佳实践通常是：**微调(行为) + RAG(知识) + Prompt(单次引导)**。

## 🧭 七、新手学习路径建议

1. **第一阶段（感知）**：学会使用主流大模型（如 Kimi、豆包、ChatGPT），掌握基本的 Prompt 技巧（角色扮演、给示例、要求输出格式）。
2. **第二阶段（理解）**：搞懂 Temperature 等参数对输出的影响，理解什么是 Token 和上下文限制。
3. **第三阶段（应用）**：了解 RAG 和 Agent 的概念，尝试使用 Coze（扣子）、Dify 等低代码平台搭建一个简单的智能体工作流。
4. **第四阶段（开发）**：学习使用 LangChain 或 AutoGen 等框架编写代码，调用 API 实现自定义的 Agent 和 RAG 系统。

> [!NOTE] 知识闭环
> 
> 大模型是“超级实习生”，干活快但容易瞎编，需要你（人类）来审核和兜底。
