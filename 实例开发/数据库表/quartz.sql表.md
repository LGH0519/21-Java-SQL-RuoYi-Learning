## `quartz.sql` 是什么？

用一个生活类比来理解：

> 把若依系统想象成一家公司。
> - `ry_20260417.sql` = 公司的**组织架构和规章制度**（有哪些部门、员工、角色、权限...）
> - `quartz.sql` = 公司的**闹钟系统**（定时提醒、自动执行任务）

---

## 两个文件的本质区别

| | `ry_20260417.sql` | `quartz.sql` |
|---|---|---|
| **来源** | 若依团队自己设计的 | Quartz 开源框架自带的（第三方） |
| **作用** | 若依业务系统的核心表（用户、角色、菜单...） | 定时任务的**底层引擎表** |
| **表名前缀** | `sys_`（若依的） | `QRTZ_`（Quartz 的） |
| **你会不会直接操作** | 会，业务开发经常用到 | **几乎不会**，由框架自动管理 |
| **删了会怎样** | 系统彻底不能用 | 定时任务功能失效，但系统其他功能正常 |

---

## `quartz.sql` 里的表是干嘛的？

Quartz 是一个**定时任务调度框架**，它需要数据库来"记住"任务信息（比如"每10秒执行一次"这个配置不能只存在内存里，重启就丢了）。

这 11 张表可以分为 **4 组**来理解：

### 第1组：核心表（你只需要理解这3张）

```
QRTZ_JOB_DETAILS    → "要做什么事"（任务定义）
QRTZ_TRIGGERS       → "什么时候做"（触发器）
QRTZ_CRON_TRIGGERS  → "用Cron表达式定义时间"（如 0/10 * * * * ?）
```

用一个类比：

| 概念 | 类比 | 对应表 |
|------|------|--------|
| **Job（任务）** | "打扫办公室"这件事 | `QRTZ_JOB_DETAILS` |
| **Trigger（触发器）** | "每天早上8点"这个闹钟 | `QRTZ_TRIGGERS` |
| **Cron Trigger** | 闹钟的具体时间规则 | `QRTZ_CRON_TRIGGERS` |
| **Simple Trigger** | 简单重复闹钟（如每10秒响一次） | `QRTZ_SIMPLE_TRIGGERS` |

### 第2组：运行状态表（框架自动管理）

| 表名 | 作用 | 类比 |
|------|------|------|
| `QRTZ_FIRED_TRIGGERS` | 记录正在执行/已触发的任务 | "当前正在打扫的人" |
| `QRTZ_SCHEDULER_STATE` | 调度器状态（集群时用） | "哪个闹钟在值班" |
| `QRTZ_LOCKS` | 悲观锁（防止多实例重复执行） | "同一件事只让一个人做" |

### 第3组：特殊触发器表（一般用不到）

| 表名 | 作用 |
|------|------|
| `QRTZ_BLOB_TRIGGERS` | 自定义类型的触发器（极少用） |
| `QRTZ_SIMPROP_TRIGGERS` | 带参数的触发器 |
| `QRTZ_CALENDARS` | 日历排除（如节假日不执行） |
| `QRTZ_PAUSED_TRIGGER_GRPS` | 被暂停的触发器组 |

## 和 `ry_20260417.sql` 中定时任务的关系

你可能注意到，`ry_20260417.sql` 里也有两张定时任务表：

```
sys_job        → 若依的定时任务表（你在页面上看到的）
sys_job_log    → 若依的定时任务日志表
```

它们的关系是这样的：

```
你在若依页面上配置定时任务
        ↓
保存到 sys_job 表（你看得懂的：任务名、cron表达式...）
        ↓
若依后端把 sys_job 的配置"翻译"成 Quartz 能懂的格式
        ↓
写入 QRTZ_JOB_DETAILS + QRTZ_TRIGGERS + QRTZ_CRON_TRIGGERS
        ↓
Quartz 引擎根据这些表自动定时执行
        ↓
执行结果写回 sys_job_log
```

**简单说**：
- `sys_job` = **你操作的界面层**（人看的）
- `QRTZ_*` 表 = **Quartz 引擎的工作层**（机器用的）

## 你需要关心 `quartz.sql` 吗？

**作为新人，基本不需要。** 原因：

1. 这 11 张表是 **Quartz 框架自动创建和维护**的，你不需要手动操作
2. 你只需要执行一次这个 SQL 建表，之后就不用管了
3. 你在若依的"定时任务"页面上操作时，后端会自动同步到这些表
4. 你开发业务功能时，几乎不会直接查询这些表

**你真正需要关注的是**：
- `ry_20260417.sql` → 若依的核心业务表，必须执行
- `quartz.sql` → 如果你要用定时任务功能，才需要执行
- `ry_test_01.sql` → 你自己创建的报名表，正在开发中

---

## 三个 SQL 文件的关系总结

```
ry_20260417.sql   → 若依系统的"地基"（必须执行，系统才能跑起来）
quartz.sql        → 定时任务的"引擎"（可选，用了定时任务才需要）
ry_test_01.sql    → 你的"扩建工程"（公务员报名功能）
```

执行顺序：先 `ry_20260417.sql` → 再 `quartz.sql` → 最后 `ry_test_01.sql`。
