## 3. `$tab.openPage()` 做了什么

真实实现位于：

[tab.js (line 66)](E:/WorkSpace/ruoyi-archive-management/frontend/src/plugins/tab.js:66)

```
openPage(title, url, params) {
  const obj = {
    path: url,
    meta: {
      title: title
    }
  }

  useTagsViewStore().addView(obj)

  return router.push({
    path: url,
    query: params
  })
}
```

这个方法主要做两件事。

### 第一件：添加顶部页签

```
useTagsViewStore().addView(obj)
```

把下面的信息加入若依的页签管理：

```
{
  path: "/system/dict-data/index/1",
  meta: {
    title: "字典数据"
  }
}
```

所以顶部会出现“字典数据”页签。

### 第二件：执行路由跳转

```
router.push({
  path: url,
  query: params
})
```

这里真正让 Vue 从当前页面跳转到目标页面。

本例没有传第三个 `params` 参数，因此没有额外的查询字符串。

注意，`openPage()` 中的第三个参数名字叫 `params`，但实际传给了：

```
query: params
```

所以它其实是查询参数，例如：

```
proxy.$tab.openPage(
  "字典数据",
  "/system/dict-data/index/1",
  {
    pageNum: 2
  }
)
```

最终可能是：

```
/system/dict-data/index/1?pageNum=2
```

这里的变量名叫 `params` 容易和 Vue Router 的路径参数混淆，但这是若依现有代码的命名。

## 4. Vue Router 匹配路由

对应路由位于：

[router/index.js (line 126)](E:/WorkSpace/ruoyi-archive-management/frontend/src/router/index.js:126)

```
{
  path: "/system/dict-data",
  component: Layout,
  hidden: true,
  permissions: ["system:dict:list"],
  children: [
    {
      path: "index/:dictId(\\d+)",
      component: () => import("@/views/system/dict/data"),
      name: "Data",
      meta: {
        title: "字典数据",
        activeMenu: "/system/dict"
      }
    }
  ]
}
```

父路径是：

```
path: "/system/dict-data"
```

子路径是：

```
path: "index/:dictId(\\d+)"
```

组合以后就是：

```
/system/dict-data/index/:dictId
```

所以这个地址：

```
/system/dict-data/index/1
```

会匹配该路由，并得到：

```
dictId = "1"
```

### `:dictId` 是什么

冒号表示动态参数：

```
:dictId
```

它可以接收不同的字典ID：

```
/system/dict-data/index/1
/system/dict-data/index/2
/system/dict-data/index/100
```

### `(\\d+)` 是什么

它表示 `dictId` 只允许是数字。

所以：

```
/system/dict-data/index/1       可以匹配
/system/dict-data/index/25      可以匹配
/system/dict-data/index/abc     不能匹配
```

## 5. 路由决定加载哪个 `.vue`

这行代码：

```
component: () => import("@/views/system/dict/data")
```

对应真实文件：

[data.vue](E:/WorkSpace/ruoyi-archive-management/frontend/src/views/system/dict/data.vue)

也就是说，Vue Router 匹配成功以后，会把当前内容区域切换为 `data.vue`。

这才是实现“切换 `.vue` 页面”的关键：

```
路由地址
    ↓ 匹配
路由配置
    ↓ component
目标.vue文件
```

`openPage()` 自己并不知道应该加载哪个 `.vue`；它只负责跳转到一个地址。真正决定加载哪个文件的是路由配置中的 `component`。

## 6. `hidden: true` 的含义

```
hidden: true
```

不是禁止访问，也不是隐藏整个页面。

它只是表示：

> 这个路由不单独显示在左侧菜单中。

因此左侧只显示“字典管理”，不会再额外出现一个“字典数据”菜单。

但是通过下面的地址仍然可以进入：

```
/system/dict-data/index/1
```

这类页面通常称为“隐藏路由页面”，经常用于：

- 详情页；
- 编辑页；
- 子数据列表；
- 分配用户页面；
- 日志详情页面。

## 9. 为什么不是直接查询字典数据

`data.vue` 首先执行：

[data.vue (line 227)](E:/WorkSpace/ruoyi-archive-management/frontend/src/views/system/dict/data.vue:227)

```
function getTypes(dictId) {
  getType(dictId).then(response => {
    queryParams.value.dictType =
      response.data.dictType

    defaultDictType.value =
      response.data.dictType

    getList()
  })
}
```

这里分为两次查询。

### 第一次：根据 `dictId` 查询字典类型

```

```

对应请求：

[type.js (line 13)](E:/WorkSpace/ruoyi-archive-management/frontend/src/api/system/dict/type.js:13)

```
export function getType(dictId) {
  return request({
    url: "/system/dict/type/" + dictId,
    method: "get"
  })
}
```

例如：

```
GET /system/dict/type/1
```

后端返回：

```
{
  dictId: 1,
  dictName: "用户性别",
  dictType: "sys_user_sex"
}
```

然后把：

```
sys_user_sex
```

放入查询条件：

```
queryParams.value.dictType =
  response.data.dictType
```

### 第二次：查询这个类型下面的数据

设置完 `dictType` 后执行：

```
getList()
```

真实代码位于：

[data.vue (line 243)](E:/WorkSpace/ruoyi-archive-management/frontend/src/views/system/dict/data.vue:243)

```
function getList() {
  loading.value = true

  listData(queryParams.value).then(response => {
    dataList.value = response.rows
    total.value = response.total
    loading.value = false
  })
}
```

对应请求：

```
GET /system/dict/data/list?dictType=sys_user_sex
```

然后返回：

```
男
女
未知
```

因此完整的数据转换过程是：

```
地址中的 dictId = 1
        ↓
查询字典类型
        ↓
取得 dictType = sys_user_sex
        ↓
按照 dictType 查询字典数据
        ↓
显示男、女、未知
```

## 10. 动态路由的权限注册

这个路由放在：

```
dynamicRoutes
```

而不是普通的：

```
constantRoutes
```

登录后，若依会根据权限过滤动态路由：

[permission.js (line 45)](E:/WorkSpace/ruoyi-archive-management/frontend/src/store/modules/permission.js:45)

```
const asyncRoutes =
  filterDynamicRoutes(dynamicRoutes)

asyncRoutes.forEach(route => {
  router.addRoute(route)
})
```

过滤条件是：

[permission.js (line 100)](E:/WorkSpace/ruoyi-archive-management/frontend/src/store/modules/permission.js:100)

```
if (route.permissions) {
  if (auth.hasPermiOr(route.permissions)) {
    res.push(route)
  }

```

字典数据路由要求：

```

```

拥有该权限时，路由才会注册进 Vue Router；没有该权限时，即使手动输入地址，也不能正常进入该页面。

## 11. 当前代码存在一个权限不一致点

你项目中的“列表”按钮使用：

```
v-hasPermi="['system:dict:edit']"
```

但目标动态路由要求：

```
permissions: ["system:dict:list"]
```

这两个权限不一样：

```
按钮显示：system:dict:edit
路由进入：system:dict:list
```

这意味着一个极端情况：

```
用户拥有 edit 权限
但没有 list 权限
```

他可能看得到“列表”按钮，但点击后目标路由没有注册，无法正常进入。

在若依默认角色配置里，拥有编辑权限的人通常也有列表权限，所以平时不容易暴露。但从语义和严谨性看，这个“列表”按钮更适合使用：

```
v-hasPermi="['system:dict:list']"
```

或者为字典数据查看设计一个更明确的权限。你没有要求修改，因此这里仅指出问题。

## 12. 对你的报名详情意味着什么

如果报名详情以后采用独立 `.vue`，可以模仿同样结构：

```
报名管理 index.vue
        ↓
点击详情
        ↓
$tab.openPage(
  "报名详情",
  "/registration/manage/detail/" + registrationId
)
        ↓
隐藏动态路由
        ↓
加载 registration/manage/detail.vue
        ↓
读取 route.params.registrationId
        ↓
请求 GET /registration/manage/{registrationId}
        ↓
显示报名详情
```

对应路由大致会是：

```
{
  path: "/registration/manage-detail",
  component: Layout,
  hidden: true,
  permissions: ["registration:manage:query"],
  children: [
    {
      path: "index/:registrationId(\\d+)",
      component: () =>
        import("@/views/registration/manage/detail"),
      name: "RegistrationDetail",
      meta: {
        title: "报名详情",
        activeMenu: "/registration/manage"
      }
    }
  ]
}
```

不过这里有一个重要区别：

- 字典“列表”页面展示一个字典类型下的多条子数据，独立页面很合理。
- 报名详情只展示一条报名记录，第一阶段使用弹窗仍然更简单。
- 将来报名详情包含学习经历、附件、审核结果等大量内容时，独立 `detail.vue` 会更合适。

这套切换方式的核心并不是“点击按钮直接切换 `.vue`”，准确说法是：

```
按钮触发路由跳转，
路由再决定加载哪个.vue文件。
```
