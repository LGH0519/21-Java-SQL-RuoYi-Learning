`@ConfigurationProperties(prefix = "ruoyi")`
`@Component`
`@Autowired`
**一句话总结：** 你自己写的代码里不需要管 `.yml`，也不需要 `new`，甚至不需要关心怎么传递数据。只要你写好 `@Component` 和 `@ConfigurationProperties`，Spring 就会在后台默默帮你把“配置读取 -> 创建对象 -> 填充数据 -> 注入使用”这整个链条全部跑通。
- Spring 项目一启动，发现 `@ConfigurationProperties(prefix = "ruoyi")`，就会自动去 `.yml` 里找 `ruoyi` 开头的配置，并填充进该类的属性中。
- 填充完数据后，Spring 会把这个类 `new` 出来。
- 类上有 `@Component` 注解，Spring 容器一看到它，就会把它登记在册，纳入自己的管理范围（IoC 容器）。
- 一旦这个对象被 Spring 容器“收养”了，它就拥有了一个特殊的身份——**Spring Bean**。
- 别处只要写下 `@Autowired`，Spring 就会立刻去容器里把这个Bean对象“塞”（注入）给你。
**Spring 容器**是一个负责创建、管理和销毁应用程序中所有对象（在 Spring 中被称为 Bean）的“大管家”。
- 在传统的开发中，程序员需要手动使用 `new` 关键字来创建对象，并自己维护对象之间的依赖关系。
- 而在 Spring 中，对象的创建和依赖关系全部交由容器负责。程序员只需要通过配置文件或注解告诉容器“我需要哪些对象”，容器就会自动帮你创建好，并在你需要时自动注入（这被称为控制反转 IoC 和依赖注入 DI）。

完整的路由查找过程应该是这样的：
1. **前端发出请求：** 浏览器发送 URL 请求（例如 `GET /system/user/list`）。
2. **请求到达 Spring：** 请求被 Spring 的核心分发器（`DispatcherServlet`）拦截。
3. **组件介入（HandlerMapping）：** `DispatcherServlet` 会把请求的 URL 交给 **`HandlerMapping` 组件**。
4. **查找注解（@RequestMapping）：** `HandlerMapping` 组件会在项目中扫描所有的 Controller 类，寻找带有 `@RequestMapping`、`@GetMapping`、`@PostMapping` 等注解的方法，看哪个方法的路径配置与当前请求的 URL 匹配。
5. **路由完成：** 找到匹配的方法（例如 `SysUserController.list()`）后，`HandlerMapping` 将这个目标方法的“指针”（官方称为 Handler，通常包含 Controller 对象和方法对象）返回给 `DispatcherServlet`，路由查找结束，准备执行

`@Configuration`
`@Bean(name = "captchaProducer")`
- **@Configuration** 本身就包含了 @Component，所以标注它的类自动被 Spring 扫描并注册为 Bean。
- **@Bean** — "产品"。标注在方法上，告诉 Spring："把我这个方法的返回值放进容器，作为一个 Bean"。@Bean 必须依附在 @Configuration 类（或 @Component 类）中才能生效。没有"车间"，"产品"就无处生产。Spring 容器管理的所有 Bean 都有一个名字（name/id），就像一个仓库里每件物品都有一个唯一编号。
- **@Component** — "通用员工工牌"。最基础的注解，告诉 Spring："把我这个类纳入容器管理"。@Configuration 继承自 @Component。也就是说，@Configuration = @Component + "我还有特殊能力：能生产 @Bean"。
- **@ConfigurationProperties(prefix = "ruoyi")** — "配置文件读卡器"。它不是独立的，必须搭配 @Component（或 @Configuration）使用。作用是：把 application.yml 中 ruoyi. 开头的配置项自动绑定到类的字段上。
-  **@Autowired** — "内部需求调拨单"。当某个 Bean 需要使用容器中的另一个 Bean 时，用 @Autowired 来注入。
```
┌─────────────────────────────────────────────────────────┐
│  Spring 启动                                            │
│                                                         │
│  ① @Configuration / @Component                          │
│     → 类被扫描，注册为 Bean                              │
│     （CaptchaConfig、RuoYiConfig 进入容器）               │
│                                                         │
│  ② @Bean                                                │
│     → 方法返回值被注册为 Bean                            │
│     （captchaProducer、captchaProducerMath 进入容器）     │
│                                                         │
│  ③ @ConfigurationProperties(prefix="ruoyi")             │
│     → 从 yml 读取配置，自动填充 RuoYiConfig 的字段        │
│     （name、version、profile 等被赋值）                   │
│                                                         │
│  ④ @Autowired / @Resource                               │
│     → 其他 Bean 从容器中获取所需的依赖                    │
│     （CaptchaController 注入 captchaProducer 等）        │
└─────────────────────────────────────────────────────────┘
```

`@PreAuthorize("@ss.hasPermi('registration:personal:query')")`
`@ss`
- **@PreAuthorize**它是 Spring Security 提供的方法权限注解，在方法执行前进行检查。
- **@ss**这里的 `ss` 不是数据库表，也不是用户角色名称，而是若依注册到 Spring 容器中的权限检查对象。ss = 若依提供的权限检查工具。表达式中的 `@` 表示从 Spring 容器中找到名为 `ss` 的对象。
- **hasPermi(...)** 表示检查当前用户是否拥有指定权限。如果当前用户具有该权限，返回 `true`；否则返回 `false`。
