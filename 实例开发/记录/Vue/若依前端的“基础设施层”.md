这些文件属于若依前端的“基础设施层”。你写报名业务时通常只会调用它们，不需要频繁修改。

先记住这条主线：

```
登录成功
  ↓
user Store 保存 Token、用户、角色、权限
  ↓
src/permission.js 路由守卫检查能否进入页面
  ↓
store/modules/permission.js 请求并生成当前用户的路由
  ↓
Sidebar/index.vue 读取侧边栏路由
  ↓
SidebarItem.vue 递归渲染成左侧菜单
  ↓
点击菜单，Vue Router 打开对应 views/*.vue
```

# 一、两份 `permission.js` 不是一回事

## 1. `src/permission.js`：路由守卫

文件：

[src/permission.js](E:/WorkSpace/ruoyi-archive-management/frontend/src/permission.js)

它更准确的名字其实应该是：

```
路由访问控制
```

它负责回答：

```
用户准备进入某个地址时，能不能进入？
进入前还需要做什么？
```

核心代码：

```
router.beforeEach(async (to, from) => {
```

含义是：

```
每次路由跳转之前，都先执行这个函数
```

例如用户准备进入：

```
/registrationManage
```

路由守卫先检查：

1. 有没有 Token；
2. 是否访问登录白名单；
3. 页面是否处于锁屏状态；
4. 用户信息是否已经加载；
5. 动态路由是否已经生成。

### 没有 Token

```
if (getToken()) {
  // 已登录
} else {
  // 未登录
}
```

如果没有 Token，并且目标不是 `/login`，就跳转到：

```
/login?redirect=原地址
```

### 有 Token，但还没有用户信息

```
if (useUserStore().roles.length === 0) {
```

表示刷新页面后，Pinia 内存中的角色还没有重新加载。

于是执行：

```
await useUserStore().getInfo()
```

取得：

- 当前用户；
- 角色；
- 权限字符。

然后执行：

```
const accessRoutes =
  await usePermissionStore().generateRoutes()
```

生成当前用户能访问的动态路由。

最后：

```
router.addRoute(route)
```

将这些路由真正注册到 Vue Router。

### 为什么刷新页面后还要重新查询？

Token 通常保存在 Cookie 中，刷新后仍存在。

但 Pinia 中的：

```
roles
permissions
sidebarRouters
```

是浏览器当前运行内存中的数据，刷新后需要重新获取。

所以流程是：

```
刷新页面
→ Token还在
→ Pinia角色为空
→ 重新查询用户信息
→ 重新生成路由
```

## 2. `store/modules/permission.js`：路由生成和保存

文件：

[store/modules/permission.js](E:/WorkSpace/ruoyi-archive-management/frontend/src/store/modules/permission.js)

它属于 Pinia Store，主要负责：

```
向后端查询路由
→ 转换路由数据
→ 保存侧边栏路由
→ 返回可访问路由
```

它不是路由守卫。

可以这样区分：

|文件|类比|主要职责|
|---|---|---|
|`src/permission.js`|门卫|判断路由跳转时该做什么|
|`store/modules/permission.js`|路由加工厂和仓库|请求、转换、保存路由|

核心入口：

```
generateRoutes() {
```

里面调用：

```
getRouters()
```

向后端请求当前用户菜单。

后端返回的数据大致类似：

```
{
  path: "registrationManage",
  component: "registration/manage/index",
  meta: {
    title: "报名管理",
    icon: "list"
  }
}
```

这时 `component` 还是字符串：

```
registration/manage/index
```

不能直接成为 Vue 组件，所以执行：

```
route.component = loadView(route.component)
```

`loadView()` 会从：

```
import.meta.glob('./../../views/**/*.vue')
```

收集到的页面中找到：

```
views/registration/manage/index.vue
```

最终完成：

```
后端字符串
registration/manage/index

        ↓ loadView()

真正可以加载的Vue组件
views/registration/manage/index.vue
```

转换完成后保存：

```
this.setSidebarRouters(
  constantRoutes.concat(sidebarRoutes)
)
```

这就是左侧菜单的数据来源。

# 二、菜单从数据库到页面的完整流程

```
sys_menu
   ↓
sys_role_menu
   ↓
当前用户拥有的角色
   ↓
后端 GET /getRouters
   ↓
返回路由 JSON
   ↓
store/modules/permission.js
   ↓
filterAsyncRouter()
   ↓
sidebarRouters
   ↓
Sidebar/index.vue
   ↓
SidebarItem.vue
   ↓
左侧菜单
```

因此，你在若依后台修改菜单后，左侧菜单不是直接读取数据库生成 HTML，而是：

```
数据库菜单
→ 后端整理成路由JSON
→ 前端Store保存
→ Vue组件渲染
```

# 三、`Sidebar/index.vue`：取得菜单数组

文件：

[Sidebar/index.vue](E:/WorkSpace/ruoyi-archive-management/frontend/src/layout/components/Sidebar/index.vue)

它取得 permission Store：

```
const permissionStore =
  usePermissionStore()
```

然后定义：

```
const sidebarRouters = computed(
  () => permissionStore.sidebarRouters
)
```

表示侧边栏路由来自：

```
permissionStore.sidebarRouters
```

模板遍历：

```
<sidebar-item
  v-for="(route, index) in sidebarRouters"
  :key="route.path + index"
  :item="route"
  :base-path="route.path"
/>
```

意思是：

```
每一条路由
→ 交给一个 SidebarItem
→ SidebarItem负责显示这一项
```

# 四、`SidebarItem.vue`：把一条路由画成菜单

文件：

[SidebarItem.vue](E:/WorkSpace/ruoyi-archive-management/frontend/src/layout/components/Sidebar/SidebarItem.vue)

它主要接收三个 props：

```
const props = defineProps({
  item: {
    type: Object,
    required: true
  },
  isNest: {
    type: Boolean,
    default: false
  },
  basePath: {
    type: String,
    default: ""
  }
})
```

含义：

|prop|作用|
|---|---|
|`item`|当前准备渲染的路由对象|
|`isNest`|当前菜单是不是嵌套在其他菜单下|
|`basePath`|当前菜单的基础路径|

## 1. 隐藏菜单

```
<div v-if="!item.hidden">
```

如果路由：

```
hidden: true
```

就不显示在侧边栏。

你建立的报名详情路由使用了：

```
hidden: true
```

所以详情页面可以访问，但不会单独出现在菜单中。

## 2. 只有一个可见子菜单

```
hasOneShowingChild(
  item.children,
  item
)
```

若一个父菜单下面只有一个可见子菜单，若依可能直接显示子菜单，减少没有必要的父级折叠。

## 3. 多个子菜单

如果存在多个子项，则显示：

```
<el-sub-menu>
```

然后再次调用自己：

```
<sidebar-item
  v-for="child in item.children"
  :item="child"
/>
```

这叫“递归组件”。

结构类似：

```
系统管理
├── 用户管理
├── 角色管理
└── 菜单管理
```

处理过程：

```
SidebarItem渲染系统管理
    ↓
发现有children
    ↓
再次使用SidebarItem渲染用户管理
    ↓
再次使用SidebarItem渲染角色管理
```

## 4. 路径拼接

```
resolvePath(child.path)
```

用于把父路径和子路径拼起来。

例如：

```
父路径：system
子路径：user
最终：/system/user
```

# 五、`store/modules` 是什么？

目录：

[store/modules](E:/WorkSpace/ruoyi-archive-management/frontend/src/store/modules)

这里使用的是 Pinia。

Store 可以理解为：

```
多个组件都能访问的前端公共数据仓库
```

普通页面中的：

```
const form = ref({})
```

通常只属于当前页面。

Store 中的数据可以被：

- 路由守卫；
- 顶部导航；
- 左侧菜单；
- 标签页；
- 业务页面；

共同读取。

当前模块作用如下：

|文件|保存和管理什么|
|---|---|
|`user.js`|Token、用户信息、角色、权限|
|`permission.js`|动态路由、侧边栏路由|
|`app.js`|侧边栏展开/收起、设备类型、组件尺寸|
|`dict.js`|已加载的字典数据|
|`settings.js`|系统标题、主题、侧边栏风格|
|`tagsView.js`|顶部已打开标签页和页面缓存|
|`lock.js`|锁屏状态|

## 1. `user.js`

文件：

[user.js](E:/WorkSpace/ruoyi-archive-management/frontend/src/store/modules/user.js)

保存：

```
state: () => ({
  token: getToken(),
  id: "",
  name: "",
  nickName: "",
  avatar: "",
  roles: [],
  permissions: []
})
```

登录时：

```
login(userInfo)
```

负责调用登录接口并保存 Token。

取得用户信息时：

```
getInfo()
```

负责保存：

```
this.roles = res.roles
this.permissions = res.permissions
```

例如报名人员可能得到：

```
roles = ["applicant"]

permissions = [
  "registration:personal:query",
  "registration:personal:save",
  "registration:personal:submit",
  "registration:personal:withdraw"
]
```

`v-hasPermi` 和 $auth 会读取这里的 `permissions`。

## 2. `dict.js`

保存已经查询过的字典数据，避免同一个字典被多个页面反复请求。

例如：

```
registration_status
registration_position
```

`proxy.useDict()` 会与字典 Store 配合使用。

## 3. `tagsView.js`

管理页面顶部的标签：

```
首页 | 报名管理 | 报名详情
```

你使用过：

```
proxy.$tab.openPage(
  "报名详情",
  detailPath
)
```

$tab 最终会调用 `tagsView` Store 增加标签页。

## 4. `app.js`

管理左侧菜单是否折叠等界面状态：

```
sidebar.opened
device
size
```

## 5. `settings.js`

管理：

- 系统标题；
- 深色主题；
- 主题颜色；
- 是否显示Logo；
- 侧边栏风格。

## 6. `lock.js`

管理锁屏功能，与普通登录退出不同。

# 六、`src/plugins` 是什么？

目录：

[plugins](E:/WorkSpace/ruoyi-archive-management/frontend/src/plugins)

这里的 plugin 不是浏览器插件，而是若依给 Vue 页面准备的公共工具。

[plugins/index.js](E:/WorkSpace/ruoyi-archive-management/frontend/src/plugins/index.js) 将工具注册到所有组件：

```
app.config.globalProperties.$tab =
  tab

app.config.globalProperties.$auth =
  auth

app.config.globalProperties.$cache =
  cache

app.config.globalProperties.$modal =
  modal

app.config.globalProperties.$download =
  download
```

因此页面中可以通过：

```
const { proxy } =
  getCurrentInstance()
```

使用：

```
proxy.$modal
proxy.$tab
proxy.$auth
proxy.$cache
proxy.$download
```

各文件作用如下：

|文件|提供的能力|示例|
|---|---|---|
|`modal.js`|消息、确认框、提示框|`proxy.$modal.msgSuccess()`|
|`tab.js`|打开、关闭、刷新标签页|`proxy.$tab.openPage()`|
|`auth.js`|判断角色和权限|`proxy.$auth.hasPermi()`|
|`cache.js`|操作 sessionStorage、localStorage|`proxy.$cache.local.set()`|
|`download.js`|下载文件、资源和压缩包|`proxy.$download.zip()`|
|`index.js`|将以上工具统一安装到 Vue|`app.use(plugins)`|

## `plugins` 和 `store` 的区别

```
plugins：提供可以调用的公共工具方法
store：保存可以被多个组件共享的状态数据
```

例如：

```
$auth.hasPermi()
```

是一个工具方法，但它判断权限时读取：

```
user Store中的permissions
```

所以两者会配合，但职责不同。

# 七、`main.js` 为什么重要？

文件：

[main.js](E:/WorkSpace/ruoyi-archive-management/frontend/src/main.js)

它是前端应用启动入口。

可以理解为：

```
创建Vue应用
→ 安装路由
→ 安装Pinia
→ 安装若依插件
→ 安装Element Plus
→ 注册全局组件和指令
→ 挂载到页面
```

关键代码：

```
app.use(router)
```

安装路由。

```
app.use(store)
```

安装 Pinia。

```
app.use(plugins)
```

安装 $modal、$tab 等若依工具。

```
directive(app)
```

安装 `v-hasPermi` 等若依指令。

```
import "./permission"
```

加载路由守卫。这里不需要接收返回值，导入文件本身就会执行其中的：

```
router.beforeEach(...)
```

最后：

```
app.mount("#app")
```

把整个 Vue 应用显示到浏览器页面。

# 九、目前需要掌握到什么程度？

## 必须理解

- `main.js` 是启动入口；
- `src/permission.js` 是路由守卫；
- `user Store` 保存用户、角色、权限；
- `permission Store` 请求并保存动态路由；
- `SidebarItem.vue` 负责把路由画成菜单；
- `plugins` 是全局公共工具；
- 菜单的源头仍然是数据库 `sys_menu`。

## 暂时只需知道用途

- `tagsView.js` 内部所有删除标签算法；
- `SidebarItem.vue` 的完整递归细节；
- `filterChildren()` 的所有路由兼容处理；
- `download.js` 的 Blob 处理；
- `settings.js` 的主题细节；
- `lock.js` 的锁屏实现。

## 一般不要随意修改

```
src/permission.js
store/modules/permission.js
layout/components/Sidebar/SidebarItem.vue
plugins/index.js
main.js
```

业务开发通常只需要：

- 配置数据库菜单与权限；
- 新增业务 `views` 页面；
- 新增业务 `api` 文件；
- 必要时在 `router/index.js` 添加隐藏路由。

这些框架文件只有在改变整个系统的菜单、路由、登录或布局机制时才需要修改。
