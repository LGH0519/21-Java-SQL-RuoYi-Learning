# Day 12：若依生成器完成档案分类与档案 CRUD

## 知识速记

CRUD 是创建、查询、更新、删除。生成器产出的是起点：必须检查字段、菜单、权限、查询、表单、接口、SQL 和数据是否一致。档案删除需保留为“待确认规则”：借阅中档案禁止删除，不能只依赖前端按钮隐藏。

## 资料

- D10 DDL、D11 生成参数映射表。
- [若依代码生成](https://doc.ruoyi.vip/ruoyi/document/htsc.html)
- 参考链：字典类型 CRUD 的页面/API/Controller/Service/Mapper/XML。

## 知识详解

分类和档案是两类基础 CRUD。分类负责归属，档案保存编号、名称、分类、状态、保管年限、物理位置。生成后要确认：列表字段不泄露不必要数据；查询条件有实际用途；编号有唯一约束；新增/修改/删除的按钮均有权限；Service 层而非仅页面阻止借阅中删除。

## 今天照做（09:00–23:00）

### 09:00–12:00：生成前冻结与备份

1. 检查 Git 状态，记录已有未提交修改；不要让生成器混入不相关改动。
2. 在 DBeaver 确认当前目标库含 D10 的表；确认表/字段注释、主键、查询字段。
3. 在生成器分别导入分类、档案表；逐项核对生成信息，截图生成参数。
4. 先生成代码预览；让 AI 审查“预期文件清单”，不接受它替代生成器盲改。

### 15:00–18:00：生成、导入与最小验证

1. 按若依生成器流程生成分类模块；先看 Git diff，确认只涉及预期前后端文件。
2. 编译/启动后端、启动前端；进入新菜单，测试列表、新增、查询、修改、删除各一次。
3. 在 Apifox 或 Network 记录一个列表和一个新增接口；DBeaver 核对数据库真实行。
4. 对档案模块重复上述操作；使用虚构测试档案，不上传真实附件。

### 19:00–23:00：AI 生成唯一性和删除保护规则

1. 先向 AI 提供规则：“archive_no 重复拒绝；借阅中档案拒绝删除”，要求输出影响文件、Service 层方案、测试用例。
2. 人工确认文件清单后，让 AI 生成最小改动；审查 Git diff。
3. 执行正常新增、重复编号、借阅中删除、非借阅中删除 4 组测试；记录 HTTP 响应和表数据。
4. 若规则未通过，回到 Service 断点而不是让 AI 重写模块。

## AI 操作卡

要求 AI 不改 DDL、不新增依赖、不更改权限框架；输出必须有“异常消息、Service 校验、测试矩阵”。

## 验收

- [ ] 分类、档案模块均可 CRUD。
- [ ] Git diff 只含预期生成/业务文件。
- [ ] 编号重复、借阅中删除均有后端失败证据。
- [ ] 页面、接口、DBeaver 三方数据一致。

## 文末答案与自测

**为什么删除保护必须在 Service？** 前端可被绕过，接口或其他调用仍可能直接进入后端。  
**通过标准：** 能拿一条档案从页面追到接口、Controller、Service、Mapper/XML、表。
