# Day 11：若依架构、代码生成器与生成前检查

## 知识速记

若依列表 CRUD 的固定链路是页面 → API → Controller → Service → Mapper → XML → 表。代码生成器适合单表/主从基础 CRUD，不自动理解借阅状态、事务和权限边界。生成前检查比生成后补洞更重要。

## 资料

- [若依代码生成说明](https://doc.ruoyi.vip/ruoyi/document/htsc.html)
- 本机模块：`ruoyi-admin`、`ruoyi-system`、`ruoyi-generator`、`ruoyi-common`。
- 真实参考链：`SysDictTypeController` 到 `SysDictTypeMapper.xml`。

## 知识详解

生成器从表结构读取字段，生成后端实体/Mapper/Service/Controller 与前端 API/页面。它只知道字段，不知道“审批通过必须事务”之类规则。生成前必须决定：表注释、字段注释、主键、查询字段、表单控件、字典类型、父菜单、权限前缀、模块名与包路径。

## AI 操作卡

AI 提示词必须写明“只输出生成参数表和风险，不改代码”；生成器任务先由你在 UI 确认每个字段，再导出代码。

## 文末答案与自测

**生成器能否自动保证借阅批准事务？** 不能；事务是自定义业务规则，需要后续 AI 生成并人工验证。  
**通过标准：** 生成前能逐项说出字段、菜单、权限和验证计划。
