# Day 07：事务、索引与 SQL 阶段验收

## 知识速记

事务把多条写操作作为整体：全成功 `COMMIT`，任一失败 `ROLLBACK`，避免半成品。索引加速常用条件/连接，但会增加写入成本；不是每列都加。借阅批准至少涉及申请状态、借阅记录、档案状态，必须同一事务。

## 知识详解

事务的核心不是背 ACID，而是识别“这些数据必须一起变”。批准借阅若只改申请、不写借阅记录，或只写记录、不改档案状态，业务会矛盾。索引优先服务：唯一档案编号、分类查询、状态/到期日查询、外键关联；需要通过真实查询验证，不为展示而堆索引。

## 文末答案与自测

**何时应该事务？** 多条写操作共同构成一个不可分割业务结果时。
