# V2：AI 协作式若依档案管理系统学习总纲

## 1. 最终目标与边界

目标不是手写一套框架代码，而是能够在事业单位网络信息部的真实工作场景中，独立完成信息管理系统的立项、需求、设计、AI/代码生成、审查、测试、发布与维护。

第一版项目为“中小企业内部档案管理系统”，角色为普通员工、档案管理员、系统管理员；包含分类、档案、附件、检索、借阅申请/撤销、审批/驳回、借出、归还、状态与逾期。暂不做多级审批、跨部门调阅、全文检索、硬件标签、短信/邮件提醒。

**代码边界：** 最终业务代码只由 AI Agent 或若依代码生成器产生；你不直接手写项目业务代码。你必须能读懂改动、审查 diff、启动、调试、测试和决定是否接受生成结果。

## 2. 固定环境与安全规则

| 项目 | 已确认环境 | 本阶段规则 |
|---|---|---|
| 后端 | RuoYi 3.9.2、Java 17、Spring Boot 4.1.0、MyBatis、Redis | 不升级依赖，不改无关配置。 |
| 前端 | Vue 3.5、Vite 6、Element Plus | 前端只学支撑后端联调的最小集。 |
| 数据库 | MySQL 8、DBeaver | 学习库与若依库分开；写操作先确认目标库。 |
| 工具 | IDEA、Git、Apifox、浏览器 DevTools、AI Agent | 每次操作保留证据；敏感信息不发送给 AI。 |

永远不提交或发送：数据库密码、JWT、Cookie、Authorization、真实人员档案、真实附件、生产地址。AI 提示词中的日志和截图必须先脱敏。

## 3. AI 协作固定闭环

```text
人工写清需求/验收
  → AI 复述并列出文件和风险
  → 人工确认范围
  → AI 或若依生成器产生最小改动
  → 人工看 Git diff
  → 编译/启动/Apifox/页面/DBeaver 验证
  → 记录结果并提交 Git
```

简单 CRUD 优先若依代码生成器；状态流转、事务、权限等自定义业务优先由 AI Agent 生成。AI 不能替代需求决策、权限边界、数据安全和验收签字。

## 6. 每日统一交付物

每个学习日结束时必须留下：当天笔记、至少一张脱敏截图、一个调试/排查记录、验收结果。项目进入 D08 后还要将需求、图、SQL、测试用例等真实产物纳入 Git；不要为凑提交而提交空文件。

## 8. 通用 AI 操作卡

```text
背景：我在 RuoYi-Vue 3.9.2 + Java 17 + MySQL 8 项目中完成 <功能>。
业务规则：<谁能做什么、状态如何变化、哪些情况必须失败>。
现有证据：<表结构/相关文件/当前报错或接口响应，敏感内容已脱敏>。
请先输出：1) 需求复述；2) 最小文件修改清单；3) 风险；4) 测试用例。
未经我确认，不要改依赖、配置、无关文件，也不要删除文件。
确认后只生成最小代码；每项改动说明原因。
```

## 9. 总验收

Day16 前必须完成至少 15 个测试场景，覆盖正常流程、权限不足、重复编号、状态非法、附件异常、事务失败。最终 README 应让另一位开发者能在本机按说明启动前后端并理解系统限制；本阶段不进行公网或单位内网部署。
