# D13 今天照做执行清单：附件上传、下载、元数据

## 上午：找复用能力（09:00–12:00）

1. [ ] IDEA 全局搜索 **CommonController**，打开后搜索 `upload`、`download`。
2. [ ] 在笔记写：上传 URL、输入形式、响应里可用字段；不要复制真实文件绝对路径。
3. [ ] 打开附件表字段字典，确认有 archiveId、原文件名、存储信息、大小、类型、上传时间。
4. [ ] 在桌面创建一个内容为“附件测试”的小文本文件，命名 `attachment-test.txt`；不要使用工作单位文件。

## 下午：上传与元数据（15:00–18:00）

1. [ ] 在现有档案详情页面或测试页面点击上传按钮；若尚无入口，先用 Apifox 调现有上传接口，按其已有参数选择文件。
2. [ ] 点击 **发送/上传**，查看响应；保存脱敏截图。
3. [ ] 用生成器/AI 生成附件元数据 CRUD 前，先让 AI 输出文件清单和关联档案校验规则。
4. [ ] 审查 diff 后保存一条附件元数据，DBeaver 查询 `archive_attachment` 核对 archiveId 与文件字段。

## 晚上：下载与异常（19:00–23:00）

1. [ ] 从附件列表点击下载；确认下载文件可打开且内容是测试文字。
2. [ ] 测：不选文件、archiveId 为空、附件 ID 不存在、无权限下载；记录页面/接口响应。
3. [ ] 在附件保存 Service 处断点，观察 archiveId 和上传返回字段；F8/F9 后移除断点。
4. [ ] 删除测试附件记录和测试文件（仅你刚创建的文件），确认未删真实文件。

## 收尾验收

- [ ] 上传、元数据、下载三步都有证据。
- [ ] 至少 4 个异常场景已测试。
- [ ] 未把真实附件、绝对路径或 token 写入文档/Git。
