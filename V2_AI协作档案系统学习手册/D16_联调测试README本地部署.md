# Day 16：全流程联调、测试、README 与本地部署演练

## 知识速记

联调是页面、接口、权限、数据库共同验证；测试用例必须包含成功和失败；README 是可复现说明，不是宣传稿；本地部署验收要求前后端独立启动、配置不泄密、他人能按步骤理解和验证项目。

## 资料

- [若依环境部署](https://doc.ruoyi.vip/ruoyi-vue/document/hjbs.html)
- D08–D15 的需求、接口、状态图、SQL、测试记录。
- `backend/pom.xml`、`frontend/package.json`，只读构建脚本。

## 知识详解

测试至少分四层：页面操作、HTTP 接口、数据库结果、后端日志/断点。一个成功提示不足以验收，必须证明数据和状态正确。README 应包含背景、功能、角色、技术栈、ER 图、启动前提、启动步骤、测试账号说明（不写真实密码）、测试案例、限制和第二版方向。

## 今天照做（09:00–23:00）

### 09:00–12:00：建立最终测试表

1. 新建 `docs/test/test-cases.md`，至少列 15 条：分类/档案 CRUD、重复编号、附件成功/失败、申请/撤销、审批/驳回、越权、借出、归还、事务失败、逾期查询。
2. 每条必须有前置数据、操作、预期接口/页面、预期数据库、实际结果、证据链接/截图。
3. 用 AI 审查测试缺口；人工确认它没有加入第一版外功能。

### 15:00–18:00：全流程联调

1. 按普通员工→管理员顺序完成一条完整测试：档案存在 → 申请 → 审批 → 借出 → 归还。
2. 对每个动作记录 Network 状态、响应、DBeaver 表数据和页面状态。
3. 执行至少 5 条失败用例；失败时以后端证据确认不是单纯前端提示。
4. 修复只通过 AI 最小改动流程进行：复述→文件清单→diff→编译→回归测试。

### 19:00–23:00：README 与本地构建演练

1. 用 AI 生成 README 草案，人工补真实路径、启动顺序、功能限制；删除密码、token、真实附件路径。
2. README 必含：项目背景、角色、功能、技术栈、ER 图链接、启动前提、后端启动、前端启动、测试数据说明、测试表、已知限制。
3. 只执行本地构建说明中已知安全命令：后端 Maven 打包、前端 `npm run build:prod`；若构建失败，记录第一条错误，不升级依赖。
4. 检查 Git status/diff；确认不含 `application*.yml` 的凭据、上传文件、构建产物或 token。提交真实文档/代码变更。

## AI 操作卡

要求 AI 先输出 README 目录和待确认占位符；所有占位符必须人工填真实、非敏感内容。AI 不得自动执行 Git push、删除文件、发布服务器或改生产配置。

## 验收

- [ ] 至少 15 条测试中含 5 条失败案例，并有证据。
- [ ] 核心借阅主路径可本地演示。
- [ ] README 可让他人理解并按步骤启动。
- [ ] Git 检查确认无敏感信息和无关文件。
- [ ] 本地构建成功，或有完整、可复现的失败记录。

## 文末答案与自测

**为什么接口 200 不能单独代表成功？** 仍需验证业务状态、数据库结果、权限边界和页面显示。  
**Day16 后先做什么？** 进入真实若依框架调用链、权限、Redis、日志和维护学习，不急于部署公网。  
**通过标准：** 能向陌生人演示核心流程，并让对方根据 README 在本机复现。
